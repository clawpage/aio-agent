## 1. 主会话与任务

主页面只有一个对话入口，不提供旧会话历史入口。新请求创建持久化任务，由独立的执行会话完成；
相关补充自动加入原任务。

- **并行**：任务运行时仍可继续发消息，默认最多 3 个执行任务并行（`PA_MAX_CONCURRENT_TURNS`），超出的排队等待。
- **过程与结果**：执行过程默认收拢为状态条，开始时附一段不超过 100 字的整体说明（只生成一次），点击查看详情。
  结果按完成时间回报到主会话，支持文件卡片、预览与下载。相关补充归入原任务后，进行中卡片跟随最新补充消息，只保留一张。
- **回答方式**：普通聊天、身份介绍和可直接回答的问题在对话中完整回复，不创建任务目录或文件；只有需要独立文件交付时
  才进入制作与验证流程。最终回复以个人助理的方式给出结果、建议和文件链接，skill、工具、命令等实现细节留在过程详情。
- **交付格式**：普通文字与简单表格用 Markdown；复杂排版、图表或交互优先用适配手机的 HTML 页面；用户指定的格式优先。
  新文档使用预装工具生成在 `workspace/tasks/<task-id>/`，临时文件与 LibreOffice 配置也在任务目录内。
- **执行权限**：沙箱内 Codex 默认完整访问且不请求审批（`approval_policy=never`，新建、恢复、派生线程与每次执行都显式设置）；
  权限只作用于容器，不开放宿主机，也不解除 MCP 隔离。派单器不指定或限制执行者的资源。

### 追问与选择

派单器不预先追问，先启动执行。执行者查过已有资料与必要来源后，只有缺少无法合理默认的用户独有条件时才提问，
可先完成不依赖答案的部分。问题显示为「等待你补充」，直接在主输入框回答会续接原执行会话。

需要用户拍板时，回答末尾可带一个 ```` ```choices ```` 代码块（JSON 列表或每行一项），显示为可点选的答案；
点选后作为回复接续该任务，已回复的选项勾选并关闭。问题与回答持久保存，刷新或重启后仍可继续。

### 引用任务

每个任务提供「引用任务」：输入框显示引用目标，可取消或切换；提交成功后清除，失败时保留引用、草稿和重试消息 ID。

- 引用的消息按被引用任务的状态直接路由，不经 Jev 与派单器判断：进行中的任务追加到当前轮次（`steer`）；
  已结束的任务用 Codex `thread/resume` 在原执行会话里继续（同一执行会话的轮次串行）。派单器只生成标题和简述。
- 未引用时，普通跟进由派单器结合最近任务自动识别。地址、条件、纠正以及同一交付物的新增要求直接追加到运行中的原任务。
- 追加是合并不是取代：原任务照常完成，卡片保留原任务的标题；只有补充明确要求停止或改做别的才算取代。执行者的最终回复要同时包含原任务的结果
  和对补充的处理。同一轮里插入过补充时，补充之前给出的最终答案（通常是原任务的）与最后的答案一起保存为结果，用分隔线隔开（Codex 执行器）。
  原任务进行中顺带问的、答案不属于原交付物的旁支问题，派单器新开任务并关联原任务。
- 补充或回答送达任务时，该任务被用户接管着的浏览器标签页自动交还给执行者（补充里会告诉执行者已交还），执行者不会一直等「交还」；
  确实还需要用户亲手操作时由执行者再次请求接管。合并保存的较早答案去掉它末尾已被后续补充回答过的提问块。
- 原任务恰好已结束时，补充作为带原结果背景的后续任务处理；送达状态不明时提示核对，不自动重发。
- 依赖前置结果的任务等前置成功后才执行，失败或未知结果不会被假定成功。

### 停止、重试与未知结果

每个任务可以单独停止。重试发送用同一消息 ID 去重；派单失败的任务尚未执行，可以重试分配。
执行结果未知时不自动重跑，重启后的在途任务会提示先核对，避免重复副作用。

### 主会话刷新与任务列表

- 主会话每 2.5 秒刷新：`GET /api/main` 返回整页内容的哈希 `version`，下次带 `?v=<version>`，未变化时只回 `{"unchanged":true}`。
- 接近顶部时自动加载更早的任务（每页 100 个），当前阅读位置不跳动。商品卡片图片、SVG 卡片与地图瓦片滚动到附近才加载，
  SVG 按声明尺寸预先占位。
- 侧栏「任务列表」共用主会话的实时状态源，优先显示待补充和执行中任务；进入详情可返回列表，主会话草稿不受影响。
- 时间按浏览器本地时区显示为「刚刚 / 几分钟前 / 今天 / 昨天 / 日期」，悬停显示完整时间。执行中显示实时经过时长，
  结束后固定为处理用时（不含分配、排队与等待补充，含执行中的等待确认）；没有实际开始记录或结果未知时不推算。

### 任务过程时间线

工具调用与思考摘要按「连续活动段」与正文混排：一段可见内容（非空正文、审批卡）就是边界，读起来是
`文本1 — 执行了 N 项操作 — 文本2 — 执行了 M 项操作 — 当前进行中`。

- 每轮最多一条活动段处于运行状态并带扫光，且始终位于该轮最后；已结束的段不参与动画，位置与展开状态不随后续事件变化。
- 每段有稳定 ID（`working:<turnId>:<seq>`），展开状态独立保存；迟到的工具输出按 `segmentOf` 写回原段。
- 模型在工具调用前发出的空 `agentMessage` 惰性建块：出现非空正文时才创建气泡，不产生空气泡也不切段；
  重复或迟到的 `item/started` 是无副作用的空操作。
- 段头如实反映状态（运行中、排队、已完成、出错、已停止、结果未知）。已结束段显示「执行了 N 项操作」或「思考摘要」；
  工具失败时保留错误提示；空的终态段不保留。用户消息、正文、审批、补充输入与错误始终独立显示。
- 只显示模型生成的推理摘要（`PA_REASONING_SUMMARY`），不展示原始思维链。段内按内容自然撑开，单个工具日志保留高度上限。
  `prefers-reduced-motion` 下关闭动画。

### 登录态与助理设定

- 登录页会重新验证 HttpOnly 会话 cookie，有效时自动进入主会话；页面回到前台、Safari 恢复或网络恢复时自动重查，
  登录页可见期间每 15 秒重试。网络故障不清除凭据。
- 配置页「助理设定 · SOUL.md」编辑助理的身份、语气与行为。原文保存在数据目录的 `SOUL.md`（0600，不进 Git，沙箱不可写），
  通过 Codex `developerInstructions` 注入主会话规划及所有执行线程（新建、resume、fork），下次规划或执行时读取最新内容。
  支持清空，最大 64 KiB，多设备编辑冲突时拒绝覆盖并保留草稿。

## 2. 派单与历史召回

派单依次经过数据库召回、倒排检索、Jev 评分、派单器决策，确定标题、简述、路由（new / `steer` / `resume`）、关联与前置依赖。
派单器只做分类，不执行任务，也不限制执行者使用文件、浏览器或工具。

- **派单模型**：owner 选择 Codex 时用 `PA_TITLE_MODEL`（默认 `gpt-6.1-sol`）；`gpt-6.1-sol` 与 `gpt-6-luna` 使用 low 推理强度，
  其他模型 high；所选模型满载时换用另一个重试一次。owner 选择 Claude Code 或 member 账号时沿用各自配置的派单模型。
  子任务使用配置页的模型，提交时冻结。
- **历史召回**：分别取最近 5 个进行中与 5 个已结束任务，再用 SQLite FTS5 倒排索引补充最多 4 个，候选总数最多 14 个。
  索引覆盖标题、用户消息（含补充）、任务结果与最新助理消息；中文按相邻两字切词、拉丁文按词切分，按内容哈希增量更新。
  简短回复会结合邻近任务标题再检索一次。
- **主会话时间线**：派单器与执行会话都拿到按时间排列的最近用户消息（时刻、原话摘录、归属任务及状态、助理最后的提问），
  最后一条标 ▶ 为本次消息。执行会话另见相关任务的创建时刻与最后提问；追加给进行中任务的补充附发送时刻与最近 6 条对话。
- **Jev 评分**：Jev 对每个候选独立给出相关性分数，并建议 new / `steer` / `resume`。分数为 0 的任务详情不传给派单器
  （用户显式引用除外）。Jev 不可用或超时（`PA_JEV_DISPATCH_TIMEOUT_SECONDS`，默认 15 秒）时派单器依据召回独立决策。
  Jev 原始回答与分数、派单器计划写入派单日志；执行会话拿到的是可读摘要，用户原话优先。
- **上下文去重**：续接同一执行会话时，已在线程前文中且未变化的任务详情只列 ID；执行约束带内容版本号，版本一致时只写一句
  「按之前的约束执行」。换模型、换执行器或线程压缩后重新完整注入。
- **结果容错**：不影响路由的小问题自动修正（去掉不存在的任务 ID、关联超过 12 个时依赖优先截断、按实际状态修正
  `steer` / `resume`、从说明文字中提取 JSON）；缺标题或结构错误时带原因重问一次，仍失败才标记「分配失败」。
- **召回监控**：每次派单记录候选及来源、搜索词、轮数、选中任务、耗时与提示词长度；手动引用的老任务用于衡量检索
  （排名、recall@上限、MRR）。配置页「历史召回」展示近 7 / 30 天统计（`GET /api/settings/recall`，仅 owner）。
- **调试模式（仅 owner）**：配置页开关（只记在当前浏览器）打开后，每条消息下方出现「派单日志」，按步骤展示候选、Jev 分数、
  派单器提示词与原始回答、重问原因、最终计划、失败原因与分阶段耗时。日志存于 `recall_events.steps_json`，保留 14 天；
  接口 `GET /api/settings/dispatch-log/<任务id>`。
- **按需查历史（`aio_history`）**：每个账号的执行会话注册 MCP 服务 `aio_history`（成员网关 `/history/<运行时令牌>/mcp`，只通向本账号）。
  `history_search` 用派单器同一套 FTS5 索引（中文两字切词、BM25，标题加权）按相关度搜本账号任务，多个关键词命中任意即可，结果给出命中处的片段
  和它在执行会话里的位置（第几个/共几个）；`history_get` 读单个任务全文、同一执行会话的前后任务，`process=true` 另附执行过程
  （工具调用与参数、命令、搜索、发言，每步一行，最多 40 步）。派单注入的相关任务只给要点：原话最多 1500 字、结果最多 2500 字，截断处注明用 `history_get` 读全文。
- **长期约定**：用户明确交代的规则、偏好、双方约定和关于用户的重要事实，执行会话用 `memory_save` 记成一句话（表 `agreements`，每条最多 300 字、每账号最多 200 条），
  改主意用 `replaces` 改写，不再适用用 `memory_forget` 删除，`memory_search` 按相关度查。新执行会话开头注入「长期约定」（规则、偏好、约定、事实依次，最多约 2500 字，
  其余提示用 `memory_search` 查），带内容版本号；续接同一会话且版本未变时只写一句「已在前文给出」。
- **资源提示**：新派单不声明文件或浏览器资源。旧计划中的 `read:`、`write:`、`workspace`、`browser` 提示仅用于排队协调或
  浏览器预热，不授予或剥夺执行权限。

## 3. 账号与权限

- **owner** 保留模型、推理强度和 SOUL 配置。**member** 的主会话与任务列表只含本账号内容，不能通过任务 ID 读取、引用或停止他人任务。
- **成员模型**：member 的派单与执行由服务端固定为管理员分配的模型与推理强度（默认 `high`，可分配 `low` / `medium`）：
  默认 `gpt-6.1-sol`（Codex，经成员模型网关使用控制面的 ChatGPT 登录），也可分配 `claude-sonnet-5-5`（Claude Code）。
  客户端模型参数被忽略；分配的模型不可用时拒绝执行，不换用其他模型。
- **可见性**：member 看不到配置入口、模型参数与 SOUL 原文；配置、模型、能力清单接口拒绝访问，JSON 与 SSE 隐去模型元数据。
  正常回答内容不做关键词过滤。
- **独立环境**：member 的容器、工作区、Codex 记忆与历史、浏览器 profile、终端、任务数据库、SOUL 与文档缓存都独立；
  新成员不复制 owner 的文件或历史。成员环境默认限制 2 GiB 内存、2 CPU、1024 个进程，禁止连接内网、宿主服务和其他沙箱，
  公网可达。网络规则由独立只读守卫容器应用，成员没有 NET_ADMIN / NET_RAW。容器共享宿主内核，这不是虚拟机级隔离。
- **成员模型网关**（`PA_MEMBER_MODEL_PORT`，默认 4902）只转发账号分配的那一个模型，沙箱内只有该账号的网关令牌：
  - Claude 成员：仅 `/v1/messages` 与 `/v1/messages/count_tokens`，模型强制改为分配值，owner 的 Claude Code 凭据在宿主侧附加；
  - GPT 成员：无状态 Responses 路由，发往 `PA_CHATGPT_CODEX_URL`，模型固定、`store:false`、去掉 `service_tier`、禁用历史响应查询，
    控制面的 ChatGPT 登录（`codex-login`）在宿主侧附加；控制面未登录时该账号报服务不可用。
- **账号路径**：主控制台为 `<主域名>/u/<用户名>`，根路径和 `/login` 登录后跳到自己的地址；同一浏览器一次只登录一个账号，
  打开别人的地址只显示「这是 X 的页面」。页面路由（`src/ui/src/route.ts`）：`/tasks`、`/tasks/<任务id>`、`/schedules`、
  `/vault`、`/usage`、`/gadget` 与 `/settings`（仅 owner）、`/workspace`（叠加在页面上，关闭即后退）。
- **工作区路径**：`<工作区域名>/u/<用户名>/...`（owner 为 `/u/owner`，兼容旧的根路径与 `/u/<账号散列>`），无需新增 DNS、TLS 或
  tunnel。前缀与工作区会话账号不一致时 401；不带前缀的子资源（如 `/jupyter/static/...`）按会话账号路由；环境启动失败时拒绝连接，
  绝不退回 owner 沙箱。各账号共用同一工作区来源，因此同一浏览器先后登录不同账号时，工作区页面的浏览器端存储共用，
  沙箱文件、进程与记忆的隔离不受影响。
- **创建账号**：`node --env-file=var/runtime.env bin/create-user.mjs <用户名>`（Quickstart 用 `.env`；compose 见部署文档）。
  随机密码写入 `var/user-secrets/<用户名>.txt`（0600），命令不打印密码、不覆盖已有账号。
- **邀请码注册**：登录页切换到注册（或打开 `/register`），填账号（2–40 位小写字母、数字、`-`、`_`）、密码（至少 12 位）和邀请码。
  邀请码由 owner 在配置页生成，格式 `XXXX-XXXX-XXXX`，一次有效，可手动作废；领用与建号在同一事务中。注册结果是普通 member。
  猜错邀请码与输错密码共用按 IP 的失败锁定。设置 `PA_INVITE_EMAIL` 后注册页显示申请邮箱。
- **分配成员模型**：`node --env-file=var/runtime.env bin/set-user-model.mjs <用户名> <gpt-6.1-sol|claude-sonnet-5-5> [low|medium|high]`，
  重启后生效；省略推理强度时不修改。分配 Claude 需要 owner 已配置 Claude Code 凭据，分配 `gpt-6.1-sol` 需要控制面已
  `codex-login`（`AIO_HOST_CODEX=on`），用量分别计入对应账号。

## 4. 浏览器

每个账号只有一个沙箱浏览器（登录状态共享），多个任务可以同时使用。

### 标签页归属

- 沙箱内的标签页服务按任务登记每个标签页（编号、任务标题、创建与结束时间；重启后按页面 ID 重新认领）：只有创建它的任务能操作
  （导航、点击、填写、按键、执行脚本、关闭），其他任务只读（正文、HTML、结构、截图、列表）。
- 回合结束后标签页保留并标记为已结束，续接时继续使用。已结束标签页超过 8 个时关闭最久未用的；浏览器空闲释放前清理全部已结束标签页。
  渲染进程崩溃的标签页立即关闭，任务改开新页。
- 派单不预先要求浏览器。执行者实际调用 `aio_tabs` 时按需检查并恢复浏览器；恢复失败只让这次网页操作报错。
  执行线程关闭了会抢占当前可见页的 `aio_browser`，并被告知不使用 `aio browser` 命令行。

### 内存让路

沙箱的浏览器、智能体与工具共用一个 cgroup 内存上限（owner 沙箱 2 GB，浏览器常占一半以上），超限时内核会结束渲染进程。
标签页服务每 5 秒读取 cgroup 工作集（扣除可回收页缓存）与 OOM 次数，按价值从低到高关闭页面：

1. 已结束任务的标签页（最久未用的先关）；
2. 用户自己打开、闲置超过 10 分钟的页；
3. 内存吃紧时，无人管理、15 分钟未换地址且未输入过的页；
4. 进行中任务正在用的那一页以外、闲置超过 1 分钟且未输入过的页（标签页最多的任务先让）。

每个进行中任务保底一页；正在用的页与用户接管中的页从不关闭。工作集超过上限 85% 时腾到 75%；打开页面时空闲不足 400 MB、
页面刚崩溃或刚发生 OOM 时直接腾到底。智能体再访问被关的页时会得知原因与原网址。`/healthz` 带出当前用量与 OOM 次数。

随包的 patchright-core 在构建时打了补丁（`scripts/patchright-patch.mjs`，版本不符时构建失败）：页面崩溃后读取页面会无限重试并卡死
标签页服务，补丁让该读取直接报错。控制面发现标签页服务连续两次无应答时，只重启该脚本自身的进程。

### 人与 AI 交接

- 用到浏览器的任务卡片有浏览器条（实时截图、页面网址、状态：AI 操作中 / 需要你操作 / 你正在操作 / 已结束）。
  每个任务的标签页开在各自的窗口里，后台窗口也能稳定截图。标签页归属执行会话，续接的任务共用同一组标签页；卡片和操作面板用网址
  （主机加路径）称呼页面，不用标签页记录里的会话名，免得续接任务的卡片看起来像别的任务。
- 执行者可能换掉标签页（新开一个、关掉旧的），内存让路也会关页面：卡片每次接管或交还后都重新读取标签页；交还时卡片上的那个已经不在，
  就交还该任务所有被用户接管的标签页，执行者不会等一个已经关掉的页面。
- 点「接管」打开操作面板（沙箱桌面 noVNC），先把该任务的窗口提到最前；页面被其他窗口盖住时点「切回这个页面」，
  需要完整桌面时点「在工作区打开」。用户控制期间，AI 不能操作或读取该标签页（列表里只显示「用户正在操作」），其他任务照常并行。
- 遇到登录、验证码、二次验证、输入密码或支付信息、付款、下单、发送消息、修改账号设置等需要本人完成或不可撤销的步骤，
  AI 调用 `browser_request_human` 说明原因后原地等待（最长 30 分钟，任务保持运行、浏览器不释放），任务卡与主会话标题显示
  「需要你操作浏览器」；点「交还给 AI」后继续。AI 不在对话中索要密码或验证码，结果不确定的操作不自动重做。

### 密码器

- AI 遇到账号密码登录页时，写出登录步骤交给 `browser_login`（`{{username}}`、`{{password}}` 占位符），系统代入密码器中的值执行，
  AI 看不到值。密码只填进 `type=password` 的框，步骤总从重新加载的页面开始；提交后清空残留密码框，填写期间任何任务不能读写该标签页。
- 出错时 AI 得到出错步骤与原因（不含凭据），同一标签页最多重试 3 次，之后请用户在浏览器里登录。AI 读取页面后用
  `browser_login_report` 报告结果，成功步骤按网站记录并在之后复用；没有步骤时退回自动识别输入框。
- 按页面所在网站查找账号：恰好一个时直接填写提交；没有或有多个时，任务卡里出现一张独立的「密码器」卡片（与任务浏览器卡片分开），
  可选择已保存账号、当场输入一次（默认存入密码器）或用 Google 登录；想自己登录就点任务浏览器卡片上的「去浏览器操作」。
- 侧栏「密码器」管理各网站账号，点「显示密码」才取回单个密码。密码以 AES-256-GCM 加密存在本账号控制数据库，密钥是数据目录下
  0600 的 `vault-key`，不进沙箱；账号只会填进保存时的网站及其子域名。
- 网站可设为「用 Google 登录」（不存密码，可指定 Gmail 账号），之后 AI 直接点网站的 Google 登录按钮；Google 要求密码或二次验证时请用户操作。
  验证码、二次验证、扫码登录仍走 `browser_request_human`。

### 浏览器身份与版本

- **身份一致**：镜像默认让 Linux Chromium 冒充 Mac UA、时区写死新加坡、关闭 GPU，这些都是反爬系统判定机器人的强信号。
  控制面在沙箱就绪时对齐：保留 Linux UA，时区用 `PA_BROWSER_TIMEZONE`（应与出口网络一致），通过软件渲染启用 WebGL；有改动时优雅重启一次浏览器。
- **较新的 Chromium**：镜像自带的 Chromium 146 在 TLS 握手阶段就被 eBay 拒绝。控制面把 xtradeb PPA 的 Chromium 154 及所缺依赖
  解包到 `/opt/aio-browser/chromium-<校验和前缀>/`（每个包校验固定 SHA-256，只解包不安装），并把浏览器守护进程指向它。
  旧版本目录在无进程使用后才删除。仅在 `PA_BROWSER_BUILD_ARCH`（默认 `aarch64`）启用；`PA_BROWSER_BUILD_PACKAGES` 可换包，
  `PA_BROWSER_BUILD=off` 回到镜像浏览器。
- **启动参数**：不用 Chrome for Testing（Cloudflare 验证会卡在「Verifying…」）；去掉会卡住 Cloudflare 的 `--use-angle=swiftshader` 与
  `--disable-site-isolation-trials`；默认 `--enable-features=AddTLSServerHandshakePadding`（缺此 TLS 扩展 eBay 拒绝握手）；关闭前进后退缓存
  （`--disable-features=BackForwardCache`，实测同一标签页连跳 5 站从 929 MB 降到 467 MB）。Cloudflare 验证在 2 核沙箱中可能需要二三十秒。
- **profile 升级**：新版 Chromium 会升级 profile。首次换用其他可执行文件前，profile（去掉缓存）备份到
  `~/.codex/aio-browser/profile-before-browser-change.tgz`（0600）；回退时先停浏览器再用备份替换 `/home/gem/.config/browser`。
  把会话绑定设备的网站（如 LinkedIn）在换版本后需重新登录。
- **镜像自带客户端**：python-server 的浏览器接口与 `mcp-server-browser` 首次使用后会以未修补的 Playwright / Puppeteer 常驻连接，
  导致页面被判为自动化。巡检在无任务、浏览器不在唤醒或恢复时断开它们；python-server 同时承载终端，只在无连接且无运行中命令时重启。

### 常驻与空闲释放

- **owner 常驻**：owner 浏览器默认一直运行，登录状态（包括会话 cookie）始终留在同一进程。若因升级或崩溃处于已释放状态，
  后台巡检自动恢复一次。需要省内存时设 `PA_BROWSER_RELEASE_IDLE=1`。
- **成员空闲释放**（`PA_MEMBER_BROWSER_RELEASE_IDLE=1`，设 `0` 改为常驻）：常驻 Chromium 约占 500 MB；实测快照加释放约 20 秒、
  释放后容器少约 370 MB，下次冷启动约 17 秒，cookie 全部恢复。智能体只使用这一个浏览器，不另起浏览器或清除站点数据。
- **何时算在用**：执行中的任务（整轮保护）、可见工作区面板里的观看者（心跳 TTL `PA_BROWSER_VIEWER_TTL_SECONDS`，默认 60 秒）、
  进行中的浏览器 / CDP / VNC 请求与 WebSocket。空闲 `PA_BROWSER_IDLE_SECONDS`（默认 300，下限 30）后释放；总开关 `PA_BROWSER_LIFECYCLE`。
  面板隐藏、关闭或页面转入后台立即释放观看租约。
- **状态**：工作区浏览器 / 桌面面板顶部显示状态、占用原因、观看数量、空闲倒计时与重试入口。`/api/browser/status` 是只读轮询，
  不唤醒也不续期。重新打开面板时按需恢复。
- **快照**：保存标签顺序、URL、选中页、滚动位置、`sessionStorage`，以及 cookies 与当前站点的 localStorage / IndexedDB，写入 0600 原子快照。
  同网址的多个标签通过临时标识区分。无法安全保存的页面（`chrome://`、有未提交输入、正在下载）会阻止释放并说明原因；
  快照失败绝不停止浏览器。
- **恢复**：重建页面并导航回原 URL（不保留 JS 堆），导航前注入按 origin 限定的 `sessionStorage` 脚本，站点存储在应用启动前导入；
  核对顺序后激活原选中页。恢复同时重建 AIO REST 与浏览器 MCP 连接（精确重启 `mcp-server-browser` 并以 `browser_tab_list` 验证）。
  失败时保留快照并如实报错，可重试，不自动重放用户操作。
- **只恢复一次**：快照只恢复一次，之后浏览器重启沿用 profile 数据。镜像每次启动会把 cookie 设为「仅限会话」，控制面在沙箱启动时写入
  管理策略 `/etc/chromium/policies/managed/aio-cookies.json`（`DefaultCookiesSetting: 1`）使 cookie 跨退出保留。
- **边界**：不删除用户 profile；不承诺保存 JS 堆、未落盘的编辑器状态或未打开站点的数据库。存储工具与标签页服务使用锁定的
  `patchright-core@1.63.0`（不调用 `Runtime.enable`，避免在每个页面留下 CDP 自动化痕迹），离线安装到 root 管理的 `/opt/aio-browser`。
- 控制面不为读状态保持浏览器运行，也不把「归属未知」当作「浏览器不存在」；无法确认归属时按保守策略处理并如实显示。

## 5. 沙箱容器空闲休眠

成员的整个沙箱容器在无人使用时停止（`PA_MEMBER_SANDBOX_RELEASE_IDLE=1`），下次使用时启动；owner 默认常驻
（`PA_SANDBOX_RELEASE_IDLE=0`）。`PA_RESIDENT_MEMBERS` 列出的成员与 owner 一样常驻并随服务启动（现有部署为语音配件账号 `betaw`）。

- **停止条件**：以下两个信号都静默满 `PA_SANDBOX_IDLE_SECONDS`（默认 300，下限 60）：
  - 沙箱在用：执行中或排队的轮次、派单中或待执行的任务、待批准请求、浏览器租约、进行中的工作区代理请求、在工作区标签页里输入；
  - 控制台在前台：页面可见时每 20 秒心跳，有效 60 秒。
- **停止顺序**：
  1. 检查容器内是否有运行中的 shell 命令，并测 10 秒平均 CPU（不含 Chromium 渲染）；有命令、CPU ≥ 5% 或读取失败均视为在用；
  2. 给浏览器做快照并释放，快照失败则不停；若浏览器还有未恢复的快照，直接停；
  3. 期间有人回来则不停；最后 `docker stop`，卷全部保留。
- **唤醒**：控制台回到前台立即预热；派单、执行、打开文件或浏览器、加载工作区页面会等待容器启动（约半分钟）。
  隐藏标签页里的编辑器自动重连与后台轮询不会唤醒。
- 休眠期间巡检与服务重启都不拉起容器，定时任务等后台工作照常。控制台不提示休眠或启动中，等待计入请求耗时；只有启动失败才提示
  「智能体暂未就绪」。

## 6. 工作区

工作区是伴随来源上的一台「小电脑」，外观参照 macOS：顶部菜单栏（当前应用、新标签页、时钟、关闭），中间桌面与一个应用窗口，
底部程序坞（浏览器、终端、文件、编辑器、笔记本、预览；owner 另有接口与 MCP，接了手机时还有「手机」）。红、黄按钮把窗口收回桌面并卸载页面，绿按钮全屏。

- **文件**：统一承担目录导航、上传、新建、预览、下载、文本编辑与删除；可转换格式的文件提供「转换」入口，工具就绪状态收在底部「文档处理」。
  对话附件经 `POST /api/sandbox/upload` 存入 `/home/gem/workspace/uploads/`。
- **终端**：紧凑会话选择器可切换 session 并恢复输出，支持新建、复制 ID、刷新与关闭。关闭运行中的会话先提示，全部关闭时显示空状态，
  不自动新建。列表只在页面可见时每 5 秒刷新，已完成但存活的 session 标为「空闲」。
- 原生界面（noVNC 桌面、code-server、JupyterLab、端口预览、MCP）及沙箱接口见 [AIO 能力清单](AIO-CAPABILITIES.md)。

### 富内容块

| 内容 | 写法 | 行为 |

| SVG 图 | ```` ```svg ```` 或 `.svg` 文件 | 在 `<img>` 中绘制（不执行脚本、不加载外部资源），可全屏、下载为白底 PNG |

  （商品页只给 path 时取 og:image 或最大图片；selector 指向图片元素时下载原图；只收 jpg / png / webp、8 MB 内），下载以该标签页身份进行。

- **地图卡片**：点卡片在地图应用中查看地点（不直接导航）。Android 用 `geo:` 交给系统选择；iPhone 与电脑首次点击时选择应用
  （苹果地图、高德、百度、Google 地图、Waze），选择记在本机 `localStorage`，卡片上「换」可重选。瓦片经 `/api/map/tiles/…` 由控制面代取并缓存。
  坐标只用查到的数值，查不到只给地址。

  服务端核对 `.svg` 内容确为 SVG。无固定宽度的图按消息宽度显示。流程、分支、时间线和关系图建议用 mermaid（竖屏优先 `flowchart TD`），其他示意图用 svg。

### 链接

- **超链接**：公网域名与公网 IP 在设备浏览器打开（正文、分享卡片、商品卡片与文档预览一致）；只有内网 IP（私有 IPv4、回环、链路本地、
  CGNAT / Tailscale、本地 IPv6）在沙箱浏览器打开，不通过解析域名猜测 IP。App 中 iOS 用 Safari 浏览面板、Android 用 Custom Tab。
- **分享卡片**：链接到分享页（`/u/<用户名>/share/<页面名>/` 或 `share?<页面名>`）时显示完整地址、复制、系统分享与打开。
- **视频**：YouTube（watch、youtu.be、Shorts、直播）与 B 站（BV / av，支持 `p=`、`t=`）单视频链接在桌面嵌入播放器（16:9，最多 4 个）；
  手机与平板改为视频卡片，在系统浏览器或 App 中打开。播放器地址由视频 ID 重新拼接（YouTube 用 `youtube-nocookie.com`），放在受限 sandbox iframe 中，
  主站 CSP 的 `frame-src` 只为此放行相应域名。播放列表、频道页与 `b23.tv` 短链不嵌入。

## 8. 文档工具

智能体可在沙箱内创建、修改、转换文档（Word / Excel / PPT 用 Python 库，格式转换与 PDF 用 LibreOffice）。
转换目标：`pdf`、`docx`、`xlsx`、`pptx`、`csv`、`txt`、`odt`、`ods`、`odp`、`html`。

- 工具依赖沙箱内的 LibreOffice、poppler-utils、中文字体与 Python 文档库，不来自 `npm ci`。容器启动后控制面在后台安装缺失部分
  （新环境约一两分钟），并把文档 skill 写给 Codex 与 Claude Code。安装失败时界面如实显示未就绪，owner 可点「安装/修复」重试。详见[运行手册](RUNBOOK.md#沙箱文档工具)。
- 所有解析与转换在沙箱内进行，控制面只以固定 argv 调用固定命令。路径先经工作区范围校验（拒绝越界、symlink 逃逸、选项注入）；
  预览均需鉴权；音视频保留 Range / 206 / 416 语义；主动内容一律以 `attachment` 下载。转换结果写成新文件，不覆盖原件。

## 9. 定时任务与每日推送

在主会话里直接说时间和要做的事，例如「每天早上 8 点查天气提醒我带伞」「每 2 小时看一下这个商品降价没」「帮我盯 10/6 Prime Day」。
定时任务属于账号，保存在控制面，与创建它的会话无关；每次运行是一个新任务。

- **规则**：派单器给出 `schedule`：`once` / `daily` / `weekly` / `monthly` / `interval` / `dates`，可带 `maxRuns` 或 `until`，以及每次要做的 `instruction`。
  一天多次用 `times: ["08:00","18:00"]`（最多 12 个）；不规律时间用 `dates`（最多 60 个）。服务端按 `PA_BROWSER_TIMEZONE` 校验并算出下次运行时间，
  规则无效时交回派单器重答。「帮我盯着…」「到时候提醒我…」类请求也按定时处理，节奏不明显时先给出可选项。说「现在先做一次」时本次照常执行。
- **执行会话工具**：每个账号的执行会话注册 MCP 服务 `aio_schedule`（成员网关 `/schedule/<运行时令牌>/mcp`，只通向本账号）：
  `schedule_create`、`schedule_list`、`schedule_change`（暂停 / 恢复 / 取消）、`schedule_update`（原地修改），校验与上限同派单器；
  Claude Code 自带的会话内计时工具
  （`CronCreate`、`CronDelete`、`CronList`、`ScheduleWakeup`）在执行轮次中禁用。循环间隔至少 15 分钟，每账号最多 20 个进行中的定时任务。
- **运行**：控制面每 30 秒检查到点任务，直接建一个已派好的任务（不经派单路由），附上次结果作为背景；执行会话被告知用户不在场，
  不提问、不再建定时任务。上一次未结束时跳过本次；停机期间错过的只补跑一次。结果显示为「定时任务「…」自动运行」。
- **管理**：侧栏「定时任务」页可修改、暂停、恢复、立即运行、删除（`PATCH /api/schedules/:id`、`POST /api/schedules/:id/:action`）；
  也可在主会话中说「暂停天气提醒」，派单器给出 `scheduleAction`。修改规则后 `maxRuns` 重新计数；已结束的任务改出新时间会重新开始，暂停的保持暂停。
  删除不影响已有运行结果。

### 每日推送

`PA_DAILY_FEED=1`（默认）时每个账号内置一个「每日推送」：owner 08:00 运行，成员依次错开 4 分钟（时段记在主库 `meta` 的 `feed_slot:<账号>`）。
只有过去 24 小时内用户发过消息才运行，否则静默跳过（手动「立即运行一次」不受限）。

- **内容**：执行会话拿到用户最近 7 天的任务记录（最新 60 条含摘要，更早的只列日期与标题，最多 800 条）和最近 14 次推送话题，挑出今天值得
  提醒的 3–8 件事；邮箱与订单物流只算其中一项，另需从近几天关注的商品和话题中挑 2–4 项实际上网查今日价格、折扣或动态并附来源
  （推送轮不受通用执行约束中「控制工作量」的限制）。新任务体现的兴趣优先；同一话题连推 3 次而无相关新任务时停推。没有内容时只回一句、不发通知；
  有内容时以手机通知推送「今日为你留意」。话题记入 `feed_history`，结果中的机器标记（`<!--feed-topics: …-->`、`<!--feed-empty-->`）不显示。
- **只读浏览**：可以打开用户已登录或任务中用过的网站（邮箱、订单、账单、关注动态），但严格只读：不发送、回复、点赞、购买、删除、
  改设置；不点开未读邮件与私信；未登录的网站跳过。
- **用户调整**：`aio_schedule` 的 `feed_get` / `feed_update` 可修改用户要求（`schedules.instruction`，不能突破只读规则）、推送时间，
  以及 `feed_memory` 中的 `care` / `avoid` / `note`（每类最多 30 条）。推送根据用户后续任务与对推送的直接回复，用 `feed_update`（`source: "feed"`）自行记录，每次最多改 3 条；用户在对话中给出的反馈由执行会话记下。
  「定时任务」页在推送卡片上显示「你的要求」和记住的条目。规划不会把「改推送」当成新的定时任务，内置推送只能用 `feed_update` 修改。
  内置推送可以暂停、恢复，不能删除；在主会话说「别再推了」会暂停它。

## 10. 语音输入

主会话输入区的麦克风按钮：点一下开始，再点一下停止（最长一分钟），识别文字追加到草稿，不自动发送。所有账号可用。

- **开启**：`PA_ASR_URL` 指向语音识别服务（`POST` 16 位单声道 WAV，返回 `{text}`），例如 muse-gadget-sdk 的 `tts-server`
  （SenseVoice；请求 `/asr?punct=1` 时加标点并去掉口头禅，只有口头禅时返回空，按钮提示「没听清」）。未配置时 `GET /api/asr` 返回 `{enabled:false}`，按钮不显示。
  现有部署复用语音配件的识别服务：`PA_ASR_URL=http://192.168.1.118:4910/asr?punct=1`（old-mb）。
- **链路**：浏览器取麦克风原始采样，降到 16 kHz 编为 WAV，经 `POST /api/asr`（JSON `{audioBase64}`，带 CSRF）交给控制面转发，只返回文字；
  录音不落盘、不进沙箱。超过 2 MB 返回 413，非 WAV 返回 400，识别服务出错或 30 秒无应答返回 502。
- **权限**：浏览器首次询问麦克风权限；App 声明了 iOS `NSMicrophoneUsageDescription` 与 Android `RECORD_AUDIO`。

## 11. 语音配件

桌面语音配件（如刷了 Muse Gadget 固件的 M5Stack CoreS3）把按住说话的内容发进一个账号：配件负责转写与朗读，只与服务端交换文字。

- **开启**：在控制面数据目录建 `gadget-token.env`（compose 为 `/data/gadget-token.env`，`PA_GADGET_TOKEN_PATH` 可改），内容
  `AIO_GADGET_TOKEN=<长随机串>`，权限 600。文件不存在时接口一律 401；令牌每次请求重新读取，更换无需重启。
- **绑定账号**：同一文件写 `AIO_GADGET_USER=<用户名>` 时，配件在该账号内执行（其环境、模型与知识库授权），owner 主会话看不到；
  用户名无效时 401；不写时代表 owner。现有部署绑定专用成员账号 `betaw`（`gpt-6.1-sol` / `low`，知识库可读写）。
- **接口**：`POST /api/gadget/messages`（`Authorization: Bearer <令牌>`，JSON `{text, clientMessageId}`）返回 202 `{id, status, done, reply, error}`；
  之后轮询 `GET /api/gadget/messages/<id>`，可带 `?wait=N`（最多 25 秒）长轮询。同一 `clientMessageId` 重发得到同一任务。不使用 cookie，因此不检查 CSRF。
- **执行**：不经派单器，直接建已派好的任务。代表 owner 时推理强度固定 medium，代表成员时用其分配的模型与推理强度。所有配件消息共用一个执行会话，
  回答按朗读要求输出（纯文本口语、一到三句、不用 Markdown、不追问）。问到其他任务时，执行会话用 `aio_history` 的 `history_search` / `history_get` 自行查询。
  每条消息是主会话中描述为「来自语音配件」的任务，完成时不发手机通知。
- **后台压缩**：共用会话某轮结束后上下文超过窗口 80%，且之后静默 3 分钟，控制面在后台执行一次 Codex 压缩（`thread/compact/start`）；
  压缩不进会话记录，期间到达的消息排在其后；沙箱休眠时不为此唤醒，Claude Code 会话不压缩。
- **用量页**：`GET /api/gadget/usage` 把 `PA_GADGET_USAGE_URL` 的 JSON 原样转给配件（5 秒超时、限 64 KB、非 JSON 返回 502；未配置 404）。
  现有部署指向 Usage HUD 的回环快照 `http://host.docker.internal:4796/gadget.json`，配件「用量」页每分钟拉取一次。
- **语音键盘**：配件「语音键盘」页点麦克风开始录音、再点一下结束；转写后发 `POST /api/gadget/dictation`（配件令牌，JSON `{text}`，最多 4000 字），
  控制面用 owner 的 Claude 凭据调 `PA_DICTATION_MODEL`（默认 `claude-haiku-4-5`，10 秒超时）去赘词、改错字、补标点，
  再交给宿主 Mac 上的键盘桥（`bin/keyboard-bridge.mjs`）粘贴到当前光标处，返回 `{text, polished}`。润色失败时照原文输入（`polished:false`）；
  Mac 未授予辅助功能 409 `not_trusted`，桥连不上 502，未配置 `PA_KEYBOARD_BRIDGE_URL` 404。键盘桥只经这个接口触达，沙箱与执行器都用不到它；
  粘贴后剪贴板恢复原样，且标记为临时内容，剪贴板历史工具不记录。
- **固件无线升级**：`GET /api/gadget/firmware` 返回当前固件信息（版本、构建时间、大小、`elfSha256`），`GET /api/gadget/firmware.bin` 下载镜像；
  未发布时 404。发布：`node bin/publish-gadget-firmware.mjs <文件>`（compose 下先 `docker cp` 进控制面容器），校验后替换到 `PA_GADGET_FIRMWARE_DIR`。
  配件每 10 分钟检查一次，空闲时下载到另一分区并重启，新固件连不上会自动回滚。
- **owner 查看**：配件绑定成员账号时，owner 侧栏出现以该账号命名的入口（`/u/owner/gadget`），只读显示配件对话记录
  （`GET /api/gadget/history?limit=&before=`，成员访问 403）。

## 12. 出图（aio_image）

在主会话说「画一张…」「把这张图背景换成…」即可。每个账号的执行会话注册 MCP 服务 `aio_image`（成员网关 `/image/<运行时令牌>/mcp`，只写本账号工作区），
工具 `image_generate`：

- **参数**：`prompt`；`path`（工作区内 `.png`，默认存入 `workspace/images/`）；`reference_paths`（工作区图片，最多 5 张，不支持 SVG）；
  可选 `transparent_background`、`size`（auto / 1024x1024 / 1536x1024 / 1024x1536）、`quality`。
- **实现**：控制面用自己的 ChatGPT 登录调用出图接口（`gpt-image-2`，`/images/generations` 或 `/images/edits`），把 PNG 写进该账号工作区。
  登录只在宿主侧使用。成员的 Codex 走成员网关、没有内置 imagegen，因此用此工具代替。
- 仅在控制面有 ChatGPT 登录时提供（`PA_HOST_CODEX=on`），使用 owner 的 ChatGPT 套餐额度，所有账号共用，不设调用限额。

## 13. 手机通知（Web Push）

在 iPhone Safari 中把一站「添加到主屏幕」（iOS 16.4+），从主屏幕打开后在侧栏点「开启手机通知」；Android 与桌面浏览器同样可用。每个账号、每台设备各自订阅。

- **触发**：任务完成、未完成或待核对，需要补充，有操作待确认，请你接管浏览器（含定时任务结果）。同一任务的后续消息替换前一条；
  控制台在前台（45 秒内有心跳）时不推送。
- **送达**：标准 Web Push，使用本部署的 VAPID 密钥（首次启动生成于 `var/vapid.json`，0600），内容端到端加密，推送服务看不到内容。
  只向已知推送服务的 https 地址发送；返回 404 / 410 的订阅自动删除。
- service worker（`/sw.js`）只显示通知、点按打开一站，不拦截请求、不做缓存。

## 14. 外部集成

以下集成都只经成员模型网关按账号转发，凭据只留在宿主进程，沙箱只拿到各自运行时的能力地址。新增网关 MCP 必须同时写入沙箱 Codex 的
受管策略 `/etc/codex/requirements.toml`，否则 Codex 会停用该线程级服务。

### Jev 决策

Jev（TypeSafe System One）根据状态和选项返回选择、各选项概率与置信度。key 从 `PA_JEV_SECRETS_FILE`（默认 `~/.config/aio-agent/jev.env`，
权限须为 600 / 400；环境变量 `TYPESAFE_API_KEY` 优先）读取。所有账号共用，用于：

- **派单评分**：见[派单与历史召回](#2-派单与历史召回)。
- **`decide` 工具**：执行会话注册 MCP 服务 `aio_decision`（成员网关 `/decision/<运行时令牌>/mcp`），参数 `question`、`options`
  （id → 含义，2–20 个）、可选 `context` 与 `rules`。每次调用的账号、问题、选项数、选择、置信度、耗时与用量记入宿主库 `decision_events`，不设限额。

没有 key 时两项都不出现。

### 知识库

设置 `PA_KB_MCP_URL`（宿主上的 streamable HTTP MCP 服务）后：

- **授权**：owner 及 `PA_KB_MCP_MEMBERS` 列出的成员可用，名单在重启时生效，移出名单后原地址返回 403。
- **接入**：获准账号的执行会话注册 `aio_kb`（成员网关 `/kb/<运行时令牌>/mcp`）。网关转发时附加 `Authorization: Bearer <令牌>` 与
  `X-Aio-User: <用户名>`。上游令牌从 `PA_KB_MCP_SECRETS_FILE`（环境变量 `KB_MCP_TOKEN` 优先）读取，缺失时不提供此功能。
- **隔离**：上游应只监听 loopback 并校验令牌；受管策略只为获准运行时放行这一条地址。上游不可达时工具调用返回 502，不影响任务其他部分。
  网关不缓存、不落库任何内容。给什么内容完全由上游决定，上游应只读并只提供这些账号可见的内容。
- **现有部署**：上游是 aio-kb 的 `kb-mcp`，除整理过的页面外还以 `kb_source` 提供页面引用原件的文字（owner 与 `cr` 可读）；
  执行会话只在需要时读原文，个人信息只引用回答所需部分。`KB_MCP_WRITERS`（现为 `betaw`）额外获得 `kb_note`：只在 workspace
  `raw/aio-notes/<用户名>/` 新建笔记，经 aio-kb 整理后才可检索。

### Home Assistant

设置 `PA_HA_MCP_URL`（如 `http://<HA 地址>:8124/api/mcp`，HA 官方 MCP Server 集成）后：

- **授权**：只有 `PA_HA_MCP_ACCOUNTS` 列出的用户名可用（owner 也需列出）。现有部署只授权 `betaw`。
- **接入**：获准账号注册 `aio_ha`（成员网关 `/ha/<运行时令牌>/mcp`），网关附加 HA 长期访问令牌（`PA_HA_MCP_SECRETS_FILE` 中的 `HA_MCP_TOKEN`；
  compose 用 `AIO_SECRET_HA_MCP` 挂载）。
- **能力范围由 HA 决定**：只提供「暴露给 Assist」的实体，工具为 HA 意图（`HassTurnOn`、`HassLightSet`、`GetLiveContext` 等）。
  收窄设备范围在 HA 中修改暴露名单；收回授权可移出 `PA_HA_MCP_ACCOUNTS` 并重启，或在 HA 中删除令牌。
- 执行会话只操作用户本次要求的设备，操作后读一次状态确认。

### 打印机

设置 `PA_PRINTER_URI`（家里网络打印机的 IPP 地址，如 `ipps://192.168.1.123/ipp/print`；支持 IPP Everywhere / PWG raster 的打印机）后：

- **授权**：只有 `PA_PRINTER_ACCOUNTS` 列出的用户名可用（owner 也需列出）。现有部署授权 `owner` 与 `cr`。
- **接入**：获准账号注册 `aio_printer`（成员网关 `/printer/<运行时令牌>/mcp`），工具为 `printer_status`（状态、缺纸卡纸、墨量、纸张）
  与 `print_file`（工作区里的 PDF 或图片；可选页码、份数 1–20、单双面、黑白）。其他格式由执行会话先在沙箱里转成 PDF。
- **流程**：该账号自己的沙箱用 `pdftoppm` 把文件渲染成 300 dpi 的 PWG raster（`src/control/printer/scripts/pwg-raster.py`，需沙箱里的 numpy 与 Pillow），
  控制面取回后以 IPP Print-Job 发给打印机；纸张按打印机当前装的纸。一次最多 50 页，同一时间只发一个作业。沙箱本身不接触打印机。
- **诚实**：打印机已停止（缺纸、卡纸等）时拒绝并说明原因；发送途中连接中断时报告“不确定是否已收到”，不自动重发。
  `ipps://` 不校验打印机的自签名证书，打印机由配置的地址确定，地址应在路由器上固定（DHCP 保留）。

### 手机（仅 owner）

owner 的 Android 手机用 USB 接在控制面所在的宿主机上，由 `bin/phone-bridge.mjs`（宿主进程，默认只监听 `127.0.0.1:4903`）提供；
控制面配置 `PA_PHONE_BRIDGE_URL` 后：

- **授权**：固定只有 owner。成员的配置不继承 owner 的手机地址，成员网关也不给成员发手机令牌；`/api/phone` 与画面接口对成员返回 403。
- **执行器工具**：owner 运行时注册 `aio_phone`（成员网关 `/phone/<运行时令牌>/mcp`），网关附加桥接令牌（`PHONE_BRIDGE_TOKEN`，
  `PA_PHONE_BRIDGE_SECRETS_FILE`；compose 用 `AIO_SECRET_PHONE_BRIDGE` 挂载）。上游是 mobile-mcp（固定版本，关闭遥测），桥接只放行作用在手机本身的工具：
  列设备与应用、启动/关闭应用、点按/长按/双击/滑动、读屏幕元素、截图（只回给调用方）、按键、打开网址、输入文字、方向、手机剪贴板、批量执行。
  会读写宿主机文件的（存截图到路径、从宿主路径装 APK、录屏、存日志）、卸载应用、改定位以及 mobile-mcp 的云手机工具一律拒绝，批量执行里的步骤同样过滤。
  中文等非 ASCII 输入需要手机上装 mobile-mcp 的 devicekit 辅助应用（`setup --devicekit`）。
- **实时画面**：工作区「手机」标签页（owner 且宿主提供时才出现）用 WebSocket `/api/phone/screen` 接收 scrcpy 的 H.264 画面，
  浏览器用 WebCodecs 解码（Safari 16.4+ / Chrome）。可直接点按、拖动、滚轮，下方有返回、主屏幕、最近应用、音量、电源键，
  文字框经手机剪贴板粘贴到当前输入框（支持中文，会覆盖手机剪贴板）。接口只接受主站来源（Origin）上的 owner 会话，会话退出后断开；
  伴随站不提供，以免沙箱生成的页面借工作区 cookie 操作手机。没人看时桥接在 15 秒后停止编码；网络慢时跳到下一个关键帧而不是积压。
- **任务卡片里的手机**：用过 `aio_phone` 的任务（执行记录里有它的工具调用），在执行中或等待补充时卡片显示手机截图（`/api/phone/screenshot`，
  桥接 `screencap`，macOS 上用 `sips` 压成 JPEG；每 10 秒刷新），点截图或「去手机操作」弹出可操作的实时画面；等待补充时另有「完成，继续」，
  替用户回复“已在手机上操作完成”，执行会话读屏确认后继续。
- **息屏**：桥接的 `PA_PHONE_SCREEN_OFF=1` 让手机自己的屏幕保持熄灭而系统照常运行（scrcpy 关闭面板电源），截图、mobile-mcp 和实时画面都不受影响。
  桥接启动时熄屏；有人按电源键唤醒并使用后，静置 2 分钟再次熄屏；被按电源键锁屏的手机保持原样。熄屏时直接点屏幕看不到画面，需先按两下电源键。
- 执行会话操作手机时，owner 能实时看到；付款、发消息、删除这类步骤先确认。用户让它读取本机短信验证码时它可以读取并填写（仅用于这次要登录的账号），
  登录/支付密码、指纹人脸由用户本人在卡片的手机画面里完成。

### 分享网页

沙箱内置 `aio-share` skill：智能体把页面目录（`/home/gem/workspace/share/<页面名>/`，入口 `index.html`）用
`python3 /home/gem/.codex/tools/aio-share/aio-share.py publish <目录>` 发布，得到公开地址
`https://<工作区域名>/u/<用户名>/share/<页面名>/`（短地址 `/u/<用户名>/share?<页面名>`）。只有公开页面，没有密码或私密模式。

- **发布**：经成员网关 `/share/<账号>/pages[/<页面名>]`，只认该运行时的分享令牌（宿主 `<数据目录>/share-token`，沙箱内 0600）。
  同名发布整体替换、链接不变；另有 `list` / `delete`。
- **存储**：快照存在宿主 `<PA_DATA_DIR>/shares/<账号>/<页面名>/`，访问时只读快照，不触碰沙箱。每页最多 200 个文件、20 MB，每账号 100 页；
  路径拒绝 `..`、隐藏文件、反斜杠与控制字符。
- **隔离**：页面位于工作区来源，响应带 `Content-Security-Policy: sandbox allow-scripts …`（无 `allow-same-origin`），读不到工作区会话、
  cookie 或 localStorage；另带 `nosniff`、`no-referrer`、`noindex`，不设置 cookie。这是全站唯一不需要登录的路径。

### 邮件（Gmail / Outlook）

每个账号的沙箱内置 `himalaya-email` skill，命令为 `himalaya`：

- **工具**：`himalaya` 与取 OAuth 令牌的 `ortie`，固定版本并按架构核对 sha256（`src/control/sandbox/seed.ts` 的 `MAIL_BINARIES`）。
  沙箱启动时缺失或版本不符才下载，装入持久卷并链接到 `/usr/local/bin`；下载失败只记日志。
- **默认只读，发送前确认**：查看命令走只读包装 `mail-ro`（不标已读）；发信、回复、转发、删除、移动、改标记必须先给出预览并得到用户本次明确确认。
  授权是完整邮箱权限，这些约束依靠 skill 与包装脚本。
- **OAuth 应用不进仓库**：`setup_accounts.py` 从同目录的 `oauth-clients.json` 读取（`{"google":{"client_id","client_secret"},"microsoft":{"client_id"}}`），
  缺失时提示管理员配置。账号令牌在沙箱内 `~/.local/share/mail-oauth/`（0600）。

## 15. Claude Code 执行器

默认只有 Codex 执行器。配置 Claude Code 凭据后，配置页出现「执行器」选项，模型列表按执行器过滤（`claude-opus-5-5`、`claude-sonnet-5-5`、
`claude-fable-5-1`，思考强度 low～max，留空按 CLI 默认）。

- **整体切换**：选中后派单与执行都由 Claude Code 完成。派单使用无工具、不落盘的一次性运行（`--tools ""`，模型 `PA_CLAUDE_CODE_AUX_MODEL`）。
  成员账号默认不提供；被分配 `claude-sonnet-5-5` 的成员经成员网关使用。
- **执行方式**：每个轮次在沙箱内启动 `claude -p`（stream-json 双向流），以 `bypassPermissions` 执行；MCP 只挂沙箱内服务（`--strict-mcp-config`）；
  SOUL.md 经 `--append-system-prompt` 注入，工作区 `AGENTS.md` 经配置目录的 `CLAUDE.md` 导入。事件翻译为与 Codex 相同的时间线条目，
  结果、停止与重连沿用同一套机制。
- **会话连续**：控制面预先指定会话 UUID，首轮 `--session-id`、之后 `--resume`。运行中补充写入同一进程，收到回显才算送达；停止通过控制通道
  `interrupt`，15 秒未停再结束进程；无结果退出的轮次标记 `unknown`。
- **切换执行器**：Codex 线程与 Claude Code 会话不能互相派生。已有任务在另一执行器上续接时新开会话，并带入此前的提问与最终回复（约 24k 字符）。
- **固定版本**：CLI 版本为 `PA_CLAUDE_CODE_VERSION`，首次使用时安装到持久卷并关闭自动升级；版本不符时重装并校验。
- **凭据**：`CLAUDE_CODE_OAUTH_TOKEN`（`claude setup-token` 生成）或 `ANTHROPIC_API_KEY`，先读环境变量，再读 `PA_CLAUDE_CODE_SECRETS_FILE`
  （权限宽于 600 / 400 拒绝）。只经 `docker exec -e <变量名>` 传入，argv 中只有变量名；凭据在沙箱进程内可见（CLI 需要读取）。
- **已知边界**：Claude Code 的子代理只以一条工具调用出现在时间线；CLI 的审批与交互式提问不接入。

## 16. 用量看板

owner 侧栏「用量看板」按账号显示每日 token 趋势、输入 / 输出 / 缓存汇总与每日明细，支持最近 7 / 30 / 90 天与单账号筛选，每 30 秒刷新。
统计时区取 `PA_BROWSER_TIMEZONE`。`GET /api/usage?days=30` 仅 owner 可访问。

计数持久保存在各账号控制数据库，覆盖 Codex / Claude 执行、派单与标题调用。缓存读写计入输入，总 token = 输入 + 输出。
历史只回填已保存的 Codex 用量事件；旧 Claude、旧派单、外部客户端、图片生成与 Jev 不计入，不推算账单或订阅额度。
口径详见[运行手册](RUNBOOK.md#13-token-用量统计)。

## 17. 界面与交互

- **配置页**：模型与思考强度在统一「配置」页（不在输入区），保存于 owner `meta`（`owner.agent_settings`），跨设备一致，每个轮次提交时冻结。
  输入区只保留附件、语音（配置了 `PA_ASR_URL` 时）、发送与停止。
- **界面语言**：默认中文；在配置页「界面语言」切换到 English（配置页仅 owner 可见，成员账号保持中文），选择存在本浏览器（`localStorage` 的 `aio.locale`），切换后页面重新加载。只翻译界面自身的文案，服务器生成的内容（任务标题、定时规则描述、错误信息等）保持原文。
- **移动端导航**：左上角按钮打开侧栏；主会话、工作区、配置、主题与退出入口都在侧栏。弹窗、预览、地图选择与操作面板从底部滑入，
  导航侧栏从左侧滑入；开启「减少动态效果」时直接开关。
- **输入区**：移动端为悬浮卡片，空白未聚焦时收成单行，聚焦或有草稿、附件、引用时展开，高度不超过可用屏幕。触屏设备上输入框与下拉框统一 16px
  （iPhone Safari 会放大字号更小的输入框且不缩回）。按钮使用图标与无障碍标签。
- **加载动画**：全站所有加载（启动页、登录恢复、页面与面板里的「正在读取…」、打开链接、上传与发送中）用同一个动画：单线条简笔勾出一站标志的轮廓（先描圆角外框，再画进站线段、绕站点画圆、出站线段，最后点上站心），停顿后淡出循环；单色线条，按钮里随按钮文字颜色，图片上为白色。页面上所有加载动画按同一时钟同步；开启「减少动态效果」时只显示画好的轮廓。
- **长消息**：用户消息与任务回复最多显示一屏可用高度，超出时点击打开约九分屏的底部阅读面板，返回后保留位置与草稿。
- **图片预览**：竖图按高度、横图按宽度完整显示，高度用 `100dvh`（iPhone Safari 的 `100vh` 大于可见区域）。
- **内网链接与操作面板**：智能体操作浏览器不会自动展开工作区。内网 IP 链接在沙箱浏览器中新开一个仅属于你的标签页（独立窗口），并弹出操作面板：
  - 点按即点击、双指拖动滚动；手机（视口 ≤ 720px）默认按 1.3 倍屏宽显示，捏合可在 1～3.2 倍之间缩放预览；电脑整屏适配；
  - 画面下方的黑色条用于左右平移，也是桌面工具栏（键盘、粘贴、回车、Tab、Esc）；键盘弹出时画面大小不变、操作栏留在键盘上方；
  - 这类标签页智能体不可见也不可操作，最多保留最近 3 个，关闭面板即关闭；标签页服务不可用时退回为打开工作区浏览器；
  - 打开过程显示加载卡片（可取消，超过 8 秒提示浏览器可能在唤醒，60 秒无结果自动放弃并说明原因）。
- **noVNC 补丁**：镜像自带的 noVNC 1.4.0 在手机上一次点按发两个键、长按会按住右键（导致「按住确认你是真人」无法通过）、捏合发送 Ctrl+滚轮
  （Chrome 会按站点记住缩放）。控制面在沙箱启动时打补丁（`src/control/sandbox/novncPatch.ts`）：一次点按一个键，长按 1 秒按住左键，双指点按为右键，
  捏合只缩放本地预览。
- **品牌与配色**：品牌名「一站」，配色语义为靛紫 = AI 在办（品牌主色）、琥珀 = 轮到你（全站唯一醒目色）、松绿 = 办完、朱红 = 出错；
  令牌定义在 `src/ui/src/styles.css` 顶部，新界面只用这些令牌。
