## 1. 主会话与任务

主页面只有一个对话入口，不提供旧会话历史入口。新请求创建持久化任务，由独立的执行会话完成；
相关补充自动加入原任务。

- **发送**：输入框里按回车换行；发送用 ⌘Enter（Mac）或 Ctrl+Enter（其他系统），也可点发送按钮。
- **并行**：任务运行时仍可继续发消息，默认最多 3 个执行任务并行（`PA_MAX_CONCURRENT_TURNS`），超出的排队等待。
- **过程与结果**：执行过程默认收拢为状态条，开始时附一段不超过 100 字的整体说明（只生成一次），点击查看详情。
  结果按完成时间回报到主会话，支持文件卡片、预览与下载。相关补充归入原任务后，进行中卡片跟随最新补充消息，只保留一张。
  主会话卡片在分配和执行阶段统一显示「在办」，使用同一状态标记，不显示分配阶段的独立动画或轮播提示；尚无执行会话时不打开空白详情。
  执行中的卡片只显示执行器最新说的一句，新的一句原地替换上一句，不逐条叠加。开始逐字写最终回复后，这一句收起，卡片收成两行（标题，用时与操作），由下方的「正在回复」卡片接着说；回复被撤下时这一句回来。
- **逐字出最终回复**：执行器（Codex）开始写最终回复（`phase: "final_answer"`）时，主会话在结果卡片的位置先出一张「正在回复」卡片，
  跟着执行会话的事件流（主会话为在跑任务本就打开的那条，`item/started` + `stream.delta`）逐字写出，到达的内容在约一秒内打完；
  卡片、图表、地图等代码块等闭合后才显示，不露出半截 JSON。回复写完、任务结束后，正式结果卡片原地接替它（同一个元素，不重新入场）。
  最终回复之后又开始了别的动作（补充送达、继续操作）或新一轮开始时，这张卡片撤下，等执行器重新作答。
  「正在回复」卡片紧跟在该任务进行中卡片下方时，标题行只写「正在回复」、不重复任务标题，两张卡片间距收紧、读作一体；中间隔着别的消息时照常带标题。
  Claude Code 执行器不标记最终回复，不逐字显示；事件流断开时退回原来的结束后整段显示。
- **回答方式**：普通聊天、身份介绍和可直接回答的问题在对话中完整回复，不创建任务目录或文件；只有需要独立文件交付时
  才进入制作与验证流程。最终回复以个人助理的方式给出结果、建议和文件链接，skill、工具、命令等实现细节留在过程详情。
- **交付格式**：普通文字与简单表格用 Markdown；复杂排版、图表或交互优先用适配手机的 HTML 页面；用户指定的格式优先。
  新文档使用预装工具生成在 `workspace/tasks/<task-id>/`，临时文件与 LibreOffice 配置也在任务目录内。
- **执行权限**：沙箱内 Codex 默认完整访问且不请求审批（`approval_policy=never`，新建、恢复、派生线程与每次执行都显式设置）；
  权限只作用于容器，不开放宿主机，也不解除 MCP 隔离。派单器不指定或限制执行者的资源。

### 追问与选择

派单器不预先追问，先启动执行。执行者查过已有资料与必要来源后，只有缺少无法合理默认的用户独有条件时才提问，
可先完成不依赖答案的部分。问题显示为「等待你补充」，直接在主输入框回答会续接原执行会话。

需要用户拍板时，回答末尾可带一个 ```` ```choices ```` 代码块（JSON 列表或每行一项），显示为可点选的答案；
点选后作为回复接续该任务，已回复的选项勾选并关闭。问题与回答持久保存，刷新或重启后仍可继续。

### 引用任务

每个任务提供「引用任务」：输入框显示引用目标，可取消或切换；提交成功后清除，失败时保留引用、草稿和重试消息 ID。

- 引用的消息按被引用任务的状态直接路由，不经 Jev 与派单器判断：进行中的任务追加到当前轮次（`steer`）；
  已结束的任务用 Codex `thread/resume` 在原执行会话里继续（同一执行会话的轮次串行）。派单器模型不运行，标题沿用被引用任务的标题，
  消息原文直接交给执行者；派单日志记为「派单器 0 轮」。
- 未引用时，普通跟进由派单器结合最近任务自动识别。地址、条件、纠正以及同一交付物的新增要求直接追加到运行中的原任务。
- 追加交给执行者按意思处理：纠正或改条件就按新要求调整（旧结论作废），追加要求或信息就并进来一起做，要求停下或改做别的就照办；卡片保留原任务的标题。
  补充若在执行者已给出答案之后才进入同一轮，执行者会再答一次：结果只记最后的答案，之前仍然有效的内容由执行者带进最终回复，被推翻的不再出现。
  原任务进行中顺带问的、答案不属于原交付物的旁支问题，派单器新开任务并关联原任务。
- 补充或回答送达任务时，该任务等着用户的浏览器标签页都自动交还给执行者：用户接管着的，以及执行者请用户操作（`browser_request_human`、密码器登录）但用户还没接管的；
  Mac 上 AI Chrome 里该任务的页面同样处理（补充里会告诉执行者已交还）。执行者那次等待随即返回，不会一直等「交还」：同一任务的浏览器调用逐个执行，
  否则后面的调用会全部排在这次等待后面（例如请用户登录 A 账号时用户改说用 B 账号，执行者就卡在「请先交还控制」）。确实还需要用户亲手操作时由执行者再次请求接管。
- 续接的会话上次做事已过 6 小时以上时，执行者会被告知上次是什么时候、距今多久：会话里的旧内容只当线索，问的是现在的情况或结果
  （实际费用、进度、预约订单状态、价格、最新消息）时先查知识库、邮件、此后的任务和相关网页有没有新东西，再回答并说明依据和时间。
- 原任务恰好已结束时，补充作为带原结果背景的后续任务处理；送达状态不明时提示核对，不自动重发。
- 依赖前置结果的任务等前置成功后才执行，失败或未知结果不会被假定成功。

### 停止、重试与未知结果

每个任务可以单独停止。重试发送用同一消息 ID 去重；派单失败的任务尚未执行，可以重试分配。
执行结果未知时不自动重跑，重启后的在途任务会提示先核对，避免重复副作用。
执行失败（`failed`）的结果卡片有「重试」：把原请求和附件作为引用该任务的补充再发一次（消息 ID `retry:<任务>:<版本>`，
同一次点击不会建出两个任务），以便接着原执行会话继续；之后有任何回复引用它，按钮就不再出现。结果未知（`unknown`）的卡片不提供重试。
有回复内容的卡片在操作行末尾保留一个低调的「举报回复」文字链接。

### 主会话刷新与任务列表

- 主会话每 2.5 秒刷新：`GET /api/main` 返回整页内容的哈希 `version`，下次带 `?v=<version>`，未变化时只回 `{"unchanged":true}`。
- 首屏只取最近 20 个任务（另加仍未结束的、以及最近刚结束的，保证状态不卡住）；接近顶部时自动加载更早的任务（每页 20 个），
  当前阅读位置不跳动：以屏幕上最靠上的那条为准（较早但很晚才完成的任务，其回复按完成时间排在中间，会插到正在读的内容上方），
  浏览器已自行保持时不再补偿；触屏惯性滑动中补偿前先停一帧结束惯性，否则 WebKit 会把位置甩到刚插进来的旧任务里。没有任何任务时不向沙箱查询标签页，新账号首屏直接返回。图文卡片图片、SVG 卡片与地图瓦片滚动到附近才加载，
  SVG 按声明尺寸预先占位。
- **新账号欢迎语**：主会话还没有任何任务时，显示一条内置的欢迎消息（智能体自我介绍、能办哪些事），下面是几个开场示例；
  示例都是体现「替你操作电脑」的任务（上网操作并截图、查资料做成 Excel、做网页发分享链接、盯价格定时提醒）；点一个直接作为一条消息发出，
  不经过输入框，也不动输入框里已有的草稿。
- 打开控制台时，界面版本检查（`GET /api/version`，背后不读库也不问沙箱）与登录检查同时发出：有版本接口的控制面直接进入主会话；
  只有没有版本接口的老控制面才再问一次 `GET /api/main?limit=1`，404 时进入旧版界面。
- 侧栏「任务列表」共用主会话的实时状态源，优先显示待补充和执行中任务；进入详情可返回列表，主会话草稿不受影响。
- 侧栏「文件库」（`/u/<用户名>/files`，所有账号都有）把 AI 在主会话里生成的文件收在一处：回复里链接或显示的工作区文件
  （`/home/gem/workspace/...`）。用户发送的附件不收，回复里再次引用的用户上传文件（`uploads/` 下）也不收；网页链接、代码块里提到的路径不算。
  `GET /api/main/files` 按任务创建时间倒序、每页 40 条返回已展示且含工作区路径的回复（执行中的回复还没展示，不算），只含本账号；
  界面用渲染消息时同一套 Markdown 解析挑出文件，所以列出的正是对话里显示成卡片或就地显示的文件。同一文件只列一次（最近出现的那次），
  按「全部 / 图片 / 文档 / 音视频 / 其他」筛选，图片以网格显示；点文件预览或下载，点来源可打开所在任务、再返回文件库。
  每次打开页面从头重读。文件之后在工作区被删改，这里不另行核对。
- 时间按浏览器本地时区显示为「刚刚 / 几分钟前 / 今天 / 昨天 / 日期」，悬停显示完整时间。执行中显示实时经过时长，
  结束后固定为处理用时（不含分配、排队与等待补充，含执行中的等待确认）；没有实际开始记录或结果未知时不推算。

### 客服卡片

运维方给某个账号送去修复说明、重做的文件等内容时，用客服卡片：它作为一条已完成的任务出现在该账号主会话末尾，
上方是「客服发来的消息」提示（不显示成用户自己的消息），卡片标题旁有「客服」标记，正文按 Markdown 显示，
工作区图片（`![…](/home/gem/workspace/…)`）从该账号自己的工作区读取。可以引用它继续追问，没有「举报回复」。
新卡片会给该账号的手机发通知。只有部署这台机器上的管理员命令 `bin/support-card.mjs` 能发，没有任何 HTTP 接口（见运行手册）；
卡片的 `client_message_id` 以 `support:` 开头，同一 `--id` 重复发送只保留一张。

### 任务过程时间线

工具调用与思考摘要按「连续活动段」与正文混排：一段可见内容（非空正文、审批卡）就是边界，读起来是
`文本1 — 执行了 N 项操作 — 文本2 — 执行了 M 项操作 — 当前进行中`。

- 任务过程页从最新往回读：先取最近约 200 个事件（`GET /api/conversations/:id/events?format=json&tail=200`，按轮次对齐，
  不会从一轮中间开始），一次建好时间线并停在底部，再从最后一个事件续接实时流；滚到顶部附近自动取更早的轮次（`&before=<事件 id>`），
  当前阅读位置不跳动。历史到达前只显示加载动画，不闪出空状态。不支持分页的旧控制面按原方式回放全部事件。
- 每轮最多一条活动段处于运行状态并带扫光，且始终位于该轮最后；已结束的段不参与动画，位置与展开状态不随后续事件变化。
- 每段有稳定 ID（`working:<turnId>:<seq>`），展开状态独立保存；迟到的工具输出按 `segmentOf` 写回原段。
- 模型在工具调用前发出的空 `agentMessage` 惰性建块：出现非空正文时才创建气泡，不产生空气泡也不切段；
  重复或迟到的 `item/started` 是无副作用的空操作。
- 段头如实反映状态（运行中、排队、已完成、出错、已停止、结果未知）。已结束段显示「执行了 N 项操作」或「思考摘要」；
  工具失败时保留错误提示；空的终态段不保留。用户消息、正文、审批、补充输入与错误始终独立显示。
- 只显示模型生成的推理摘要（`PA_REASONING_SUMMARY`），不展示原始思维链。段内按内容自然撑开，单个工具日志保留高度上限。
  `prefers-reduced-motion` 下关闭动画。

### 登录态与助理设定

- 登录页会重新验证 HttpOnly 会话 cookie，有效时自动进入主会话；页面回到前台、Safari 恢复或网络恢复时自动重查，
  登录页可见期间每 15 秒重试。网络故障不清除凭据。
- **无网打开**：service worker（`/sw.js`）保存最近一次打开的控制台页面及其构建文件。打开控制台总是先走网络，
  服务器有回应就是最新部署的界面；只有网络不通（或隧道/边缘返回 5xx）时才打开保存的页面。这时登录状态无法核对，
  不显示登录表单，而显示「现在连不上一站」（区分设备没联网与服务器连不上）和「重试」；之后第一次核对成功即整页重载，
  换成最新线上界面。`/api` 与其他来源从不经过缓存，所以离线时不显示任务数据。App（Android WebView、iOS WKWebView）
  与浏览器/主屏幕版共用这一机制；从没联网打开过的设备仍无保存的页面。
- 配置页「助理设定 · SOUL.md」编辑助理的身份、语气与行为。原文保存在数据目录的 `SOUL.md`（0600，不进 Git，沙箱不可写），
  通过 Codex `developerInstructions` 注入主会话规划及所有执行线程（新建、resume、fork），下次规划或执行时读取最新内容。
  支持清空，最大 64 KiB，多设备编辑冲突时拒绝覆盖并保留草稿。默认内容为英文（2026-10-15 起；回复语言仍跟随用户所写的语言），
  从未改过、仍是旧中文默认的账号在下次读取时自动换成英文版。

## 2. 派单与历史召回

派单依次经过数据库召回、倒排检索、Jev 评分、派单器决策，确定标题、简述、路由（new / `steer` / `resume`）、关联与前置依赖；Jev 有把握时跳过派单器（见「Jev 直派」）。
派单器只做分类，不执行任务，也不限制执行者使用文件、浏览器或工具。

- **派单模型**：owner 选择 Codex 时用 `PA_TITLE_MODEL`（默认 `gpt-6.1-sol`）；`gpt-6.1-sol` 与 `gpt-6-luna` 使用 low 推理强度，
  其他模型 high；所选模型满载时换用另一个重试一次。owner 选择 Claude Code 或 member 账号时沿用各自配置的派单模型。
  子任务使用配置页的模型，提交时冻结。
- **历史召回**：分别取最近 5 个进行中与 5 个已结束任务，再用 SQLite FTS5 倒排索引补充最多 4 个，候选总数最多 14 个。
  索引覆盖标题、用户消息（含补充）、任务结果与最新助理消息；中文按相邻两字切词、拉丁文按词切分，按内容哈希增量更新。
  简短回复会结合邻近任务标题再检索一次。
- **按会话派单**：一个任务和续接它的任务共用一个执行会话，派单把整条会话当一个候选，由会话里最新的任务代表（`steer` / `resume` 都落到它上），
  并附「这是第几轮、最初的标题与请求」；召回命中会话里较早的任务也归到这条会话，不重复占候选名额。时间线里较早轮次的消息同样标到最新任务上。
  这样 Jev 与派单器只判断「接这个会话还是开新任务」，不会在同一会话的前后轮次之间分概率（上线前 93% 的派单候选里有同一会话的多个任务）。
  新任务关联某个会话时，执行会话拿到它的第一轮和最近两轮（第一轮通常是主要结果），其余用 `history_get` 查，关联总数最多 12 个。
- **主会话时间线**：派单器与执行会话都拿到按时间排列的最近用户消息（时刻、原话摘录、归属任务及状态、助理最后的提问），
  最后一条标 ▶ 为本次消息。执行会话另见相关任务的创建时刻与最后提问；追加给进行中任务的补充附发送时刻与最近 6 条对话。
- **Jev 评分**：Jev 对每个候选独立给出相关性分数，并建议 new / `steer` / `resume`。分数为 0 的任务详情不传给派单器。Jev 不可用或超时（`PA_JEV_DISPATCH_TIMEOUT_SECONDS`，默认 15 秒）时派单器依据召回独立决策。
  Jev 原始回答与分数、派单器计划写入派单日志；执行会话拿到的是可读摘要，用户原话优先。
- **Jev 直派**：Jev 路由建议的概率高于 `PA_JEV_DIRECT_PROBABILITY`（默认 0.9）时，直接按它派单，不调用派单器：新任务把 Jev 相关度 ≥0.5 的候选作为关联
  （最多 12 个，无前置依赖），`steer` / `resume` 关联原任务；建议的任务已不能这样续接（状态变了）时仍交给派单器。执行会话立刻开始，
  先用消息前 40 字作临时标题，同时用小模型起一个不超过 20 字的短标题（owner 用 `gpt-6-luna` low，member 用其分配的模型，
  选 Claude Code 时用辅助模型），回来后改名，不阻塞执行；起名失败就保留临时标题。追加给进行中任务的补充沿用原任务标题，不起名。
  直派不识别定时任务，「每天提醒我…」这类由执行会话的定时工具建立。派单日志的计划带 `Routed by Jev directly` 简述。
  依据：2026-10 线上 1028 条派单里，Jev 概率 >0.9 的 382 条与派单器最终决定一致 96.6%（≤0.9 时为 76.6%）。
- **上下文去重**：续接同一执行会话时，已在线程前文中且未变化的任务详情只列 ID；执行约束带内容版本号，版本一致时只写一句
  「按之前的约束执行」。换模型、换执行器或线程压缩后重新完整注入。
- **结果容错**：不影响路由的小问题自动修正（去掉不存在的任务 ID、关联超过 12 个时依赖优先截断、按实际状态修正
  `steer` / `resume`、从说明文字中提取 JSON）；缺标题或结构错误时带原因重问一次，仍失败才标记「分配失败」。
- **召回监控**：每次派单记录候选及来源、搜索词、轮数、选中任务、耗时与提示词长度；手动引用的老任务用于衡量检索
  （排名、recall@上限、MRR）。配置页「历史召回」展示近 7 / 30 天统计（`GET /api/settings/recall`，仅 owner）。
- **调试模式（仅 owner）**：配置页开关（只记在当前浏览器）打开后，每条消息下方出现「派单日志」，按步骤展示候选、Jev 分数、
  派单器提示词与原始回答、重问原因、最终计划、失败原因与分阶段耗时。日志存于 `recall_events.steps_json`，保留 14 天；
  接口 `GET /api/settings/dispatch-log/<任务id>`。
- **按需查历史（`aio_history`）**：每个账号的执行会话注册 MCP 服务 `aio_history`（成员网关 `/history/<运行时令牌>/mcp`，只通向本账号）。
  `history_search` 用派单器同一套 FTS5 索引（中文两字切词、BM25，标题加权）按相关度搜本账号任务，多个关键词命中任意即可，结果给出命中处的片段
  和它在执行会话里的位置（第几个/共几个）；`history_get` 读单个任务全文、同一执行会话的前后任务，`process=true` 另附执行过程
  （工具调用与参数、命令、搜索、发言，每步一行，最多 40 步）。派单注入的相关任务只给要点：原话最多 1500 字、结果最多 2500 字，截断处注明用 `history_get` 读全文。
- **长期约定**：用户明确交代的规则、偏好、双方约定和关于用户的重要事实，执行会话用 `memory_save` 记成一句话（表 `agreements`，每条最多 300 字、每账号最多 200 条），
  改主意用 `replaces` 改写，不再适用用 `memory_forget` 删除，`memory_search` 按相关度查。新执行会话开头注入「长期约定」（规则、偏好、约定、事实依次，最多约 2500 字，
  其余提示用 `memory_search` 查），带内容版本号；续接同一会话且版本未变时只写一句「已在前文给出」。
- **资源提示**：新派单不声明文件或浏览器资源。旧计划中的 `read:`、`write:`、`workspace`、`browser` 提示仅用于排队协调或
  浏览器预热，不授予或剥夺执行权限。

### 个人知识库（`aio_task_kb`）

每个账号一个，只属于这个账号：由该账号的**知识管家**从做过的任务里整理出实体、主题、做法和事实，连成关系图，每条陈述都带来源。设计见 [任务知识库设计](TASK-KB.md)。

- **存在哪、谁能写**：表 `kb_*` 在控制面的账号数据库里，不在沙箱。没有任何写工具或写地址：管家每次运行是一个一次性、只读的 Codex 会话（所有账号统一 `gpt-6.1-sol` low，member 经成员网关），不挂任何 MCP 工具（只读会话、审批 never 时工具调用会被自动拒绝），只能用 shell 读任务目录；控制面先替它查好每条消息最相关的已有节点（含 id 与陈述）放进材料，它最后回答一份 JSON 修改单；控制面的写入内核（`src/control/taskKb/kernel.ts`）逐项校验后在一个事务里写入，有一项不合格就整份退回，带原因让管家重答一次，仍不合格则这批消息记一次失败（三次后标 failed）。
- **校验**：来源必须是本账号的任务；引用的原话必须逐字出现在该任务的消息、结果或工具输出里，或出现在 `tasks/<任务id>/` 下的文件里（文件指纹由内核计算）；网址必须是该任务打开或提到过的；领域必须在本账号的领域表里（默认 12 个，管家可新增英文短名并写说明）；新节点必须至少有一条带来源的陈述；证件号、卡号（Luhn）、SSN、「密码/验证码是…」一律拒收。
- **两条进库路径**：① 任务以 completed 结束后自动排队（聊天、没用过工具的任务、定时任务与每日推送、直接回答的不排）；管家读到的是任务原话与补充、结果、执行过程（含截断后的工具输出）、任务目录文件清单。② 任务进行中，任何本账号 agent 可用 `kb_propose` 递条子（add / correct / outdated / wrong），证据按同样规则当场校验；correct / outdated / wrong 一到，被指向的节点立刻在 `kb_search`、`kb_get`、派单注入里显示「有待处理的更正」，直到管家处理。
- **管家什么时候跑**：同一账号同时最多一个；只在沙箱容器开着（idle 状态 running 或 dozing；小睡只释放浏览器，管家不用浏览器）且本账号没有执行中、排队中的任务时跑，从不为此唤醒或拖住沙箱；更正类一分钟内、其他十分钟攒批或满 10 条，一批最多 10 条、约 10 万字材料（一次回答最多 120 项修改），有积压时上一批结束 10 秒后接着跑、遇到任务在跑 1 分钟后再试。用量照常计入账号（不单列）。
- **owner 回溯**：owner 首次启动时把最近 14 天完成的任务一次性排队（`meta.task_kb.backfill_v1` 记已做）；队列按完成时间从新到旧读，新完成的任务不排在回溯后面；member 不回溯，从开通后的新任务开始。
- **读**：执行会话注册 `aio_task_kb`（成员网关 `/task-kb/<运行时令牌>/mcp`，只通向本账号）：`kb_search` / `kb_get` / `kb_neighbors` / `kb_source` / `kb_propose` / `kb_propose_status`；Claude Code 执行器同样挂载。派单时按本次消息取最相关的最多 5 个节点（约 800 字）注入执行会话开头，同一会话同版本不重复。沙箱内另有 skill `aio-kb` 与 CLI `tools/aio-kb/aio-kb.py`（同一只读+提议地址）。
- **文件副本**：每次变更后（沙箱醒着时）重写 `workspace/kb/INDEX.md`（按领域列出所有节点和关系）与 `workspace/kb/wiki/<领域>/<节点>.md`；文件头注明是生成文件，改了会被覆盖。
- **wiki**：节点被任务 `kb_get` 读过至少 3 次、来源来自至少 2 个任务、且不全是推断，才能成为候选；管家写稿后由另一个一次性会话对照来源核对，通过才发布，每账号最多 50 页。
- **页面**：所有账号的「知识库」页（`/knowledge`）按领域浏览、看每条陈述的来源与待处理更正、删除一个节点或整个领域（物理删除，账本只记「被谁删了」）、整体开关（关闭后不再整理新任务、不再注入）。接口 `GET /api/knowledge`、`GET/DELETE /api/knowledge/nodes/<id>`、`DELETE /api/knowledge/domains/<名>`、`POST /api/knowledge/settings`。
- **与家庭知识库**：与 `aio_kb`（owner 与 cr 共享的家庭信息）并行，互不写入；家庭成员资料以家庭知识库为准。

## 3. 账号与权限

- **owner** 保留模型、推理强度和 SOUL 配置。**member** 的主会话与任务列表只含本账号内容，不能通过任务 ID 读取、引用或停止他人任务。
- **成员模型**：member 的派单与执行由服务端固定为管理员分配的模型与推理强度（默认 `high`，可分配 `low` / `medium`）：
  默认 `gpt-6.1-sol`（Codex，经成员模型网关使用控制面的 ChatGPT 登录），也可分配 `claude-sonnet-5-5`（Claude Code）。
  客户端模型参数被忽略；分配的模型不可用时拒绝执行，不换用其他模型。
- **可见性**：member 看不到配置入口、模型参数与 SOUL 原文；配置、模型、能力清单接口拒绝访问，JSON 与 SSE 隐去模型元数据。
  正常回答内容不做关键词过滤。
- **独立环境**：member 的容器、工作区、Codex 记忆与历史、浏览器 profile、终端、任务数据库、SOUL 与文档缓存都独立；
  新成员不复制 owner 的文件或历史。成员环境默认限制 2 GiB 内存、2 CPU、1024 个进程，禁止连接内网、宿主服务和其他沙箱，
  公网可达。网络规则由独立只读守卫容器应用，成员没有 NET_ADMIN / NET_RAW。容器共享宿主内核，这不是虚拟机级隔离。
- **成员模型网关**（`PA_MEMBER_MODEL_PORT`，默认 4902）只转发账号分配的那一个模型，沙箱内只有该账号的网关令牌：
  - Claude 成员：仅 `/v1/messages` 与 `/v1/messages/count_tokens`，模型强制改为分配值，owner 的 Claude Code 凭据在宿主侧附加；
  - GPT 成员：无状态 Responses 路由，发往 `PA_CHATGPT_CODEX_URL`，模型固定、`store:false`、去掉 `service_tier`、禁用历史响应查询，
    控制面的 ChatGPT 登录（`codex-login`）在宿主侧附加；控制面未登录时该账号报服务不可用。
    Codex 每次请求都重发整个会话历史，工具在之前回合返回的图片（如 `view_image` 看过的截图）转发前换成一句说明，
    只保留当前回合的图片和用户自己上传的图片；否则反复改图的会话会越积越大，超过请求上限（128 MB）后整个会话无法再执行。
    ChatGPT 偶尔会对这个共用登录短暂回 429（限流）：成员的 Codex 自己几秒内重试几次就放弃、任务直接失败。网关在开始回传前先等：
    按 `Retry-After`（或 `retry-after-ms`）等，没有就按 1、2、4、8、16、30 秒退避，单次最多等 30 秒、总共最多 60 秒，成员断开即停；
    用量上限（`usage_limit_reached` 等）或要求等更久的不硬等，原样转回并带上 `Retry-After`。两条路由的上游错误都记日志（状态、
    `Retry-After`、错误正文前 300 字，不含凭据），`Retry-After` 都随错误转回（Claude Code 自己会照它等）。
    仍然失败的轮次显示为「执行失败：模型服务这会儿太忙（限流）……请过一两分钟再发一次」，不再是英文原文。
- **账号路径**：主控制台为 `<主域名>/u/<用户名>`，根路径和 `/login` 登录后跳到自己的地址；同一浏览器一次只登录一个账号，
  打开别人的地址只显示「这是 X 的页面」。页面路由（`src/ui/src/route.ts`）：`/tasks`、`/tasks/<任务id>`、`/schedules`、
  `/vault`、`/usage`、`/analytics`、`/gadget` 与 `/settings`（仅 owner）、`/workspace`（叠加在页面上，关闭即后退）。
- **工作区路径**：`<工作区域名>/u/<用户名>/...`（owner 为 `/u/owner`，兼容旧的根路径与 `/u/<账号散列>`），无需新增 DNS、TLS 或
  tunnel。前缀与工作区会话账号不一致时 401；不带前缀的子资源（如 `/jupyter/static/...`）按会话账号路由；环境启动失败时拒绝连接，
  绝不退回 owner 沙箱。各账号共用同一工作区来源，因此同一浏览器先后登录不同账号时，工作区页面的浏览器端存储共用，
  沙箱文件、进程与记忆的隔离不受影响。
- **创建账号**：`node --env-file=var/runtime.env bin/create-user.mjs <用户名>`（Quickstart 用 `.env`；compose 见部署文档）。
  随机密码写入 `var/user-secrets/<用户名>.txt`（0600），命令不打印密码、不覆盖已有账号。
- **邮箱账号**：账号以邮箱标识（`owners.email`，小写保存、唯一）。新账号的用户名（即 `/u/<用户名>` 地址和配置里引用的账号名）由邮箱前缀自动生成
  （小写，非 `a-z0-9_-` 字符换成 `-`；被占用或是保留名 `owner`、`spare` 时追加 4 位随机后缀）。邮箱之前已有的账号、以及 `bin/create-user.mjs`
  按用户名创建的账号，自动得到隐藏的占位邮箱 `<用户名>@clawpage.ai`（`email_placeholder=1`，数据库迁移与插入触发器补齐）：
  界面和 `/api/auth/session` 都不显示它（`email: null`），但它占用该邮箱，注册时同样视为已注册。登录框填邮箱（不区分大小写），
  老账号继续用原用户名登录。配置页「账户与隐私」显示当前账号的邮箱（老账号显示用户名）。注册不发验证邮件。
- **注册**：登录页切换到注册（或打开 `/register`），填邮箱和密码（至少 12 位）；也可用 Google 首次认证，直接以 Google 邮箱为账号邮箱
  （该邮箱已被密码账号注册时拒绝，不自动关联）。现有账户总数不足 20 时免邀请码，达到 20 后必须填写邀请码；owner、管理员创建的成员与审核账户均计入总数。人数检查、邀请码领用与建号在同一写事务内，跨密码/Google 的并发注册不能超出免邀请码名额。
  邀请码由 owner 在配置页生成，格式 `XXXX-XXXX-XXXX`，一次有效，可手动作废；领用与建号在同一事务中。注册结果是普通 member。
  猜错邀请码与输错密码共用按 IP 的失败锁定。设置 `PA_INVITE_EMAIL` 后注册页显示申请邮箱。
- **分配成员模型**：`node --env-file=var/runtime.env bin/set-user-model.mjs <用户名> <gpt-6.1-sol|claude-sonnet-5-5> [low|medium|high]`，
  重启后生效；省略推理强度时不修改。分配 Claude 需要 owner 已配置 Claude Code 凭据，分配 `gpt-6.1-sol` 需要控制面已
  `codex-login`（`AIO_HOST_CODEX=on`），用量分别计入对应账号。

## 4. 浏览器

每个账号只有一个沙箱浏览器（登录状态共享），多个任务可以同时使用。连了 Mac 的账号另有用户自己 Mac 上的 Chrome
（`aio_user_browser`，见「手机」之后的「Mac 上的浏览器」），两者并存：执行会话优先用 Mac 上的 AI Chrome，用不了时自动改用沙箱浏览器。

### 标签页归属

- 沙箱内的标签页服务按任务登记每个标签页（编号、任务标题、创建与结束时间；重启后按页面 ID 重新认领）：只有创建它的任务能操作
  （导航、点击、填写、按键、执行脚本、关闭），其他任务只读（正文、HTML、结构、截图、列表）。
- 回合结束后标签页保留并标记为已结束，续接时继续使用。已结束标签页超过 8 个时关闭最久未用的；浏览器空闲释放前清理全部已结束标签页。
  渲染进程崩溃的标签页立即关闭，任务改开新页。
- 派单不预先要求浏览器。执行者实际调用 `aio_tabs` 时按需检查并恢复浏览器；恢复失败只让这次网页操作报错。
  执行线程关闭了会抢占当前可见页的 `aio_browser`，并被告知不使用 `aio browser` 命令行。

### 内存让路

沙箱的浏览器、智能体与工具共用一个 cgroup 内存上限（owner 沙箱 2 GB，浏览器常占一半以上），超限时内核会结束渲染进程。
标签页服务每 5 秒读取 cgroup 工作集（扣除可回收页缓存）与 OOM 次数，按价值从低到高关闭页面：

1. 已结束任务的标签页（最久未用的先关）；
2. 用户自己打开、闲置超过 10 分钟的页；
3. 内存吃紧时，无人管理、15 分钟未换地址且未输入过的页；
4. 进行中任务正在用的那一页以外、闲置超过 1 分钟且未输入过的页（标签页最多的任务先让）。

每个进行中任务保底一页；正在用的页与用户接管中的页从不关闭。工作集超过上限 85% 时腾到 75%；打开页面时空闲不足 400 MB、
页面刚崩溃或刚发生 OOM 时直接腾到底。智能体再访问被关的页时会得知原因与原网址。`/healthz` 带出当前用量与 OOM 次数。

随包的 patchright-core 在构建时打了补丁（`scripts/patchright-patch.mjs`，版本不符时构建失败）：页面崩溃后读取页面会无限重试并卡死
标签页服务，补丁让该读取直接报错。控制面发现标签页服务连续两次无应答时，只重启该脚本自身的进程。

### 人与 AI 交接

- 用到浏览器的任务卡片有浏览器条：默认收成一行横条（状态：AI 操作中 / 需要你操作 / 你正在操作 / 已结束、页面网址、接管/交还等按钮，需要你操作时下面多一行原因），
  点横条才展开实时截图；收起时不截图。
  每个任务的标签页开在各自的窗口里，后台窗口也能稳定截图。标签页归属执行会话，续接的任务共用同一组标签页；卡片和操作面板用网址
  （主机加路径）称呼页面，不用标签页记录里的会话名，免得续接任务的卡片看起来像别的任务。
- 执行者可能换掉标签页（新开一个、关掉旧的），内存让路也会关页面：卡片每次接管或交还后都重新读取标签页；交还时卡片上的那个已经不在，
  就交还该任务所有被用户接管的标签页，执行者不会等一个已经关掉的页面。
- 点「接管」打开操作面板（沙箱桌面 noVNC），先把该任务的窗口提到最前；页面被其他窗口盖住时点「切回这个页面」，
  需要完整桌面时点「在工作区打开」。用户控制期间，AI 不能操作或读取该标签页（列表里只显示「用户正在操作」），其他任务照常并行。
- 遇到登录、验证码、二次验证、输入密码或支付信息、付款、下单、发送消息、修改账号设置等需要本人完成或不可撤销的步骤，
  AI 调用 `browser_request_human` 说明原因后原地等待（最长 30 分钟，任务保持运行、浏览器不释放），任务卡与主会话标题显示
  「需要你操作浏览器」；点「交还给 AI」后继续。AI 不在对话中索要密码或验证码，结果不确定的操作不自动重做。

### 密码器

- AI 遇到账号密码登录页时，写出登录步骤交给 `browser_login`（`{{username}}`、`{{password}}` 占位符），系统代入密码器中的值执行，
  AI 看不到值。密码只填进 `type=password` 的框，步骤总从重新加载的页面开始；提交后清空残留密码框，填写期间任何任务不能读写该标签页。
- 出错时 AI 得到出错步骤与原因（不含凭据），同一标签页最多重试 3 次，之后请用户在浏览器里登录。AI 读取页面后用
  `browser_login_report` 报告结果，成功步骤按网站记录并在之后复用；没有步骤时退回自动识别输入框。
- 按页面所在网站查找账号：恰好一个时直接填写提交；没有或有多个时，任务卡里出现一张独立的「密码器」卡片（与任务浏览器卡片分开），
  可选择已保存账号、当场输入一次（默认存入密码器）或用 Google 登录；想自己登录就点任务浏览器卡片上的「去浏览器操作」。
- 侧栏「密码器」管理各网站账号，点「显示密码」才取回单个密码。密码以 AES-256-GCM 加密存在本账号控制数据库，密钥是数据目录下
  0600 的 `vault-key`，不进沙箱；账号只会填进保存时的网站及其子域名。
- 网站可设为「用 Google 登录」（不存密码，可指定 Gmail 账号），之后 AI 直接点网站的 Google 登录按钮；Google 要求密码或二次验证时请用户操作。
  验证码、二次验证、扫码登录仍走 `browser_request_human`。

### 浏览器身份与版本

- **身份一致**：镜像默认让 Linux Chromium 冒充 Mac UA、时区写死新加坡、关闭 GPU，这些都是反爬系统判定机器人的强信号。
  控制面在沙箱就绪时对齐：保留 Linux UA，时区用 `PA_BROWSER_TIMEZONE`（应与出口网络一致），通过软件渲染启用 WebGL；有改动时优雅重启一次浏览器。
- **较新的 Chromium**：镜像自带的 Chromium 146 在 TLS 握手阶段就被 eBay 拒绝。控制面把 xtradeb PPA 的 Chromium 154 及所缺依赖
  解包到 `/opt/aio-browser/chromium-<校验和前缀>/`（每个包校验固定 SHA-256，只解包不安装），并把浏览器守护进程指向它。
  旧版本目录在无进程使用后才删除。仅在 `PA_BROWSER_BUILD_ARCH`（默认 `aarch64`）启用；`PA_BROWSER_BUILD_PACKAGES` 可换包，
  `PA_BROWSER_BUILD=off` 回到镜像浏览器。
- **启动参数**：不用 Chrome for Testing（Cloudflare 验证会卡在「Verifying…」）；去掉会卡住 Cloudflare 的 `--use-angle=swiftshader` 与
  `--disable-site-isolation-trials`；默认 `--enable-features=AddTLSServerHandshakePadding`（缺此 TLS 扩展 eBay 拒绝握手）；关闭前进后退缓存
  （`--disable-features=BackForwardCache`，实测同一标签页连跳 5 站从 929 MB 降到 467 MB）。Cloudflare 验证在 2 核沙箱中可能需要二三十秒。
- **profile 升级**：新版 Chromium 会升级 profile。首次换用其他可执行文件前，profile（去掉缓存）备份到
  `~/.codex/aio-browser/profile-before-browser-change.tgz`（0600）；回退时先停浏览器再用备份替换 `/home/gem/.config/browser`。
  把会话绑定设备的网站（如 LinkedIn）在换版本后需重新登录。
- **镜像自带客户端**：python-server 的浏览器接口与 `mcp-server-browser` 首次使用后会以未修补的 Playwright / Puppeteer 常驻连接，
  导致页面被判为自动化。巡检在无任务、浏览器不在唤醒或恢复时断开它们；python-server 同时承载终端，只在无连接且无运行中命令时重启。

### 常驻与空闲释放

- **按需运行，登录不丢**：owner 与成员的浏览器都在空闲后释放、下次用到时启动（`PA_BROWSER_RELEASE_IDLE=1` /
  `PA_MEMBER_BROWSER_RELEASE_IDLE=1`，设 `0` 改为常驻；常驻时后台巡检发现它被释放会自动恢复一次）。登录不靠进程常驻：
  持久 cookie 留在卷上的 profile（管理策略防止退出时清掉），只在内存里的会话 cookie 与当前站点的 localStorage / IndexedDB
  随释放前的快照导出，恢复时只补回 profile 缺少的部分、不覆盖更新的登录；快照导不出存储就不释放。2026-10-14 在 owner
  浏览器实测一次释放与恢复：快照 3875 个 cookie，恢复后 3874 个（1 个期间过期），56 个会话 cookie 全部回来，262 个站点。
  仍可能要重新登录的只有站点自己按「无访问时长」失效的会话（释放期间没有页面在刷新它），这类站点用工作区的「保留浏览器」（最长
  `PA_BROWSER_KEEP_ALIVE_SECONDS`）。
- **成员空闲释放**：常驻 Chromium 约占 500 MB；实测快照加释放约 20 秒、
  释放后容器少约 370 MB，下次冷启动约 17 秒，cookie 全部恢复。智能体只使用这一个浏览器，不另起浏览器或清除站点数据。
- **何时算在用**：执行中的任务（整轮保护）、可见工作区面板里的观看者（心跳 TTL `PA_BROWSER_VIEWER_TTL_SECONDS`，默认 60 秒）、
  进行中的浏览器 / CDP / VNC 请求与 WebSocket。空闲 `PA_BROWSER_IDLE_SECONDS`（默认 180，下限 30）后释放；总开关 `PA_BROWSER_LIFECYCLE`。
  面板隐藏、关闭或页面转入后台立即释放观看租约。页面可见但 5 分钟没有任何操作（鼠标、键盘、触摸；在沙箱桌面里的操作由 noVNC 回报）
  也按隐藏处理：浏览器面板与任务里的桌面弹窗卸载画面、释放租约，有人再操作时自动接回。面板的「保留浏览器」开关最多保留
  `PA_BROWSER_KEEP_ALIVE_SECONDS`（默认 7200），API 调用方的保留同样不超过这个上限。
- **状态**：工作区浏览器 / 桌面面板顶部显示状态、占用原因、观看数量、空闲倒计时与重试入口。`/api/browser/status` 是只读轮询，
  不唤醒也不续期。重新打开面板时按需恢复。
- **快照**：保存标签顺序、URL、选中页、滚动位置、`sessionStorage`，以及 cookies 与当前站点的 localStorage / IndexedDB，写入 0600 原子快照。
  同网址的多个标签通过临时标识区分。无法安全保存的页面（`chrome://`、有未提交输入、正在下载）会阻止释放并说明原因；
  快照失败绝不停止浏览器。只有「未提交输入」有期限：没人使用浏览器满 `PA_BROWSER_DIRTY_INPUT_GRACE_SECONDS`（默认 1800）后照常快照释放，
  只丢输入框里的字（阅读器的页码框这类页面自己填的值也会被判为输入，曾让一个浏览器挂了 3 天）。
- **恢复**：重建页面并导航回原 URL（不保留 JS 堆），导航前注入按 origin 限定的 `sessionStorage` 脚本，站点存储在应用启动前导入；
  核对顺序后激活原选中页。恢复同时重建 AIO REST 与浏览器 MCP 连接（精确重启 `mcp-server-browser` 并以 `browser_tab_list` 验证）。
  失败时保留快照并如实报错，可重试，不自动重放用户操作。
- **只恢复一次**：快照只恢复一次，之后浏览器重启沿用 profile 数据。镜像每次启动会把 cookie 设为「仅限会话」，控制面在沙箱启动时写入
  管理策略 `/etc/chromium/policies/managed/aio-cookies.json`（`DefaultCookiesSetting: 1`）使 cookie 跨退出保留。
- **边界**：不删除用户 profile；不承诺保存 JS 堆、未落盘的编辑器状态或未打开站点的数据库。存储工具与标签页服务使用锁定的
  `patchright-core@1.63.0`（不调用 `Runtime.enable`，避免在每个页面留下 CDP 自动化痕迹），离线安装到 root 管理的 `/opt/aio-browser`。
- 控制面不为读状态保持浏览器运行，也不把「归属未知」当作「浏览器不存在」；无法确认归属时按保守策略处理并如实显示。

## 5. 沙箱容器空闲休眠

owner 与成员的整个沙箱容器都在无人使用时停止（`PA_SANDBOX_RELEASE_IDLE=1` / `PA_MEMBER_SANDBOX_RELEASE_IDLE=1`，设 `0` 改为常驻），
下次使用时启动。`PA_RESIDENT_MEMBERS` 列出的成员常驻并随服务启动（现有部署为语音配件账号 `betaw`）。
owner 容器休眠期间新成员的端口隔离规则先记下，容器下次启动时写入。

- **预备沙箱**（`PA_SPARE_SANDBOX=1`，默认开）：服务始终预先建好一个空白成员沙箱（容器、三个卷、Codex CLI、浏览器），
  记在 `meta.spare_user_id`，没有账号行，不能登录，也不计入 20 个免邀请码名额，不跑每日推送；它像常驻成员一样不因空闲小睡或停容器（服务启动时也会拉起），
  下一个自助注册（密码或 Google）直接接手这个 id，进来时容器、Codex 与浏览器都已在运行，不用等冷启动；
  接手时丢弃预备期的运行数据库，账号从空库开始，随后立刻开始准备下一个。管理员用 `bin/create-user.mjs` 建的账号不使用预备沙箱。

- **两级空闲**：先「小睡」再停止。冷启动（容器从停止到可用）无法做到 3 秒内：镜像自身启动约 3 秒（不开浏览器时；开机就启动 Chromium 则约 5 秒），
  所以没人用满 `PA_SANDBOX_IDLE_SECONDS`（默认 180）只小睡：给浏览器做快照并释放（owner 的常驻浏览器也释放），容器保留，
  约 350–400 MB；再有人用时立即可用（不经冷启动，浏览器在第一次用到时从快照恢复）。小睡累计满 `PA_SANDBOX_COLD_SECONDS`
  （默认 7200）才真正停止容器；节点可用内存（容器内 `/proc/meminfo` 的 `MemAvailable`，即整个 Docker 虚拟机）低于
  `PA_SANDBOX_PARK_BELOW_FREE_MB`（默认 4096）时小睡中的沙箱立即停止。`PA_SANDBOX_COLD_SECONDS` 不大于空闲时长则不小睡、直接停止。
- **停止条件**：以下两个信号都静默满上面的时长（小睡 `PA_SANDBOX_IDLE_SECONDS`，下限 60）：
  - 沙箱在用：执行中或排队的轮次、派单中或待执行的任务、待批准请求、浏览器租约、进行中的工作区代理请求、在工作区标签页里输入；
  - 控制台在前台：页面可见且 5 分钟内有人操作过时每 20 秒心跳，有效 60 秒。只是开着不动的窗口不算（曾让 owner 沙箱连跑 21 小时）。
- **停止顺序**：
  1. 检查容器内是否有运行中的 shell 命令，并测 10 秒平均 CPU（不含 Chromium 渲染）；有命令、CPU ≥ 5% 或读取失败均视为在用；
  2. 给浏览器做快照并释放，快照失败则不停；若浏览器还有未恢复的快照，直接停；
  3. 期间有人回来则不停；最后 `docker stop`，卷全部保留。
- **唤醒**：小睡中的沙箱立即可用；已停止的容器在控制台回到前台时立即预热，派单、执行、打开文件或浏览器、加载工作区页面会等待
  冷启动。冷启动的提速：停止前已释放的浏览器在开机时不再由镜像启动（控制面给镜像的 `gem_init.sh` 打补丁，看
  `/opt/aio-browser/boot-released` 标记；标记由浏览器释放写入、再次启动时删除），第一次用到时从快照恢复；sandboxd 健康检查
  0.25 秒一轮，网络隔离与用户/属主检查并行；工作区种子文件、Codex CLI 校验并行写入；Codex 会话与浏览器准备并行。
  日志 `sandbox container provisioned`（`nodeMs` / `provisionMs`）与 `codex session established`（`ms`）带各段耗时。
  隐藏标签页里的编辑器自动重连与后台轮询不会唤醒。
- 休眠期间巡检与服务重启都不拉起容器，定时任务等后台工作照常。控制台不提示休眠或启动中，等待计入请求耗时；只有启动失败才提示
  「智能体暂未就绪」。

## 6. 工作区

工作区是伴随来源上的一台「小电脑」，外观参照 macOS：顶部菜单栏（当前应用、新标签页、时钟、关闭），中间桌面与一个应用窗口，
底部程序坞（沙盒浏览器、Mac 浏览器、终端、文件、编辑器、笔记本、预览、手机；owner 另有接口与 MCP）。红、黄按钮把窗口收回桌面并卸载页面，绿按钮全屏。
两个浏览器分开：「沙盒浏览器」（指南针图标）是云端沙箱的桌面（noVNC，`aio_tabs`）；「Mac 浏览器」（笔记本电脑图标）是连接的 Mac 上 AI 专用的 Chrome（`aio_user_browser`，见「Mac 上的浏览器」）。
手机上程序坞的图标按宽度缩小，360 宽也不用横向滚动。

- **文件**：统一承担目录导航、上传、新建、预览、下载、文本编辑与删除；可转换格式的文件提供「转换」入口，工具就绪状态收在底部「文档处理」。
  对话附件经 `POST /api/sandbox/upload` 存入 `/home/gem/workspace/uploads/`。一条消息最多 20 个附件（`src/common/attachments.ts`，输入区与
  `POST /api/tasks` 共用这个数）；一次多选超出剩余名额时只加入前面的，并在输入区上方提示「一次最多发 20 个附件，已加入前 N 个」，不再悄悄丢掉。
- **终端**：紧凑会话选择器可切换 session 并恢复输出，支持新建、复制 ID、刷新与关闭。关闭运行中的会话先提示，全部关闭时显示空状态，
  不自动新建。列表只在页面可见时每 5 秒刷新，已完成但存活的 session 标为「空闲」。
- **编辑器与笔记本按需运行**：code-server 与 JupyterLab 合计每个沙箱约 300 MB，不再随容器启动（控制面在启动时把镜像 supervisord
  配置改为 `autostart=false`，下次容器启动起生效；Node.js REPL 同样关掉开机启动，由镜像 API 在运行代码时自行拉起）。第一次打开
  编辑器或笔记本页面时启动并等它可用，`PA_SANDBOX_PROGRAM_IDLE_SECONDS`（默认 900）内没有请求或连接流量就停掉。健康检查只要求终端就绪。
- **标签页内存预算**：沙箱内的标签页服务在工作集超过 1 GB（`AIO_TABS_MEM_BUDGET_MB`）时先关已结束任务的标签与本人闲置 10 分钟的标签；
  更激进的回收（无人跟踪的页面、运行中任务的多余标签）仍只在接近容器上限时进行。
- 原生界面（noVNC 桌面、code-server、JupyterLab、端口预览、MCP）及沙箱接口见 [AIO 能力清单](AIO-CAPABILITIES.md)。

| 地图卡片 | ```` ```map ```` JSON | `name`、`address`、`lat`/`lng`（高德 / 腾讯坐标加 `"coord": "gcj02"`）；无坐标时由控制面定位（配置 Google key 时用 Google Geocoding，否则 Nominatim） |
| SVG 图 | ```` ```svg ```` 或 `.svg` 文件 | 在 `<img>` 中绘制（不执行脚本、不加载外部资源），可全屏、下载为白底 PNG |
| 流程图 | ```` ```mermaid ```` | 首次出现时按需加载 Mermaid（strict 安全级别），之后与 SVG 相同 |
| 选项 | ```` ```choices ```` | 见[追问与选择](#追问与选择) |

- **图文卡片**：介绍或比较几样值得配图看的具体东西，代替宽表格：商品、酒店、餐厅、景点、活动、文章、视频、帖子、菜谱、App 等。
  `subtitle` 写来源或类别（商店、地点与类型、作者与网站），`tags` 是营业时间、距离、时长这类短标签（最多 4 个），`text` 是一两句介绍，
  `action` 是链接上的字（默认「去看看」）。旧名 `name`、`store`、`description` 等仍可识别。有价格的按商品图显示（完整显示、白底），
  其余图片铺满画框。图片用真实图：执行者用 `browser_save_image` 存入任务目录再引用（详情页只给 path 时取 og:image 或最大图片；
  selector 指向图片元素时下载原图；只收 jpg / png / webp、8 MB 内），下载以该标签页身份进行。没有图或取不到时卡片只排文字；解析失败的块显示为代码。
- **地图卡片**：点卡片在地图应用中查看地点（不直接导航）。Android 用 `geo:` 交给系统选择；iPhone 与电脑首次点击时选择应用
  （苹果地图、高德、百度、Google 地图、Waze），选择记在本机 `localStorage`，卡片上「换」可重选。地图由控制面代取，浏览器不直连地图服务：
  配置 `PA_GOOGLE_MAPS_API_KEY` 时是一张 Google 静态地图（`/api/map/static`，标记由 Google 绘制，国内偏移由 Google 处理；
  控制面不缓存图片，只靠浏览器缓存一天，坐标最多缓存 30 天，符合 Google 条款），取图失败时退回 OpenStreetMap；
  否则用 OpenStreetMap 瓦片（`/api/map/tiles/…`，控制面缓存）。界面经 `GET /api/map` 得知当前地图来源。
  坐标只用查到的数值，查不到只给地址。
- **SVG 与流程图**：SVG 最多 100 万字符，Mermaid 最多 2 万字符；画不出时显示源码。`/api/documents/image` 返回 SVG 时附加 `sandbox` CSP，
  服务端核对 `.svg` 内容确为 SVG。无固定宽度的图按消息宽度显示。流程、分支、时间线和关系图建议用 mermaid（竖屏优先 `flowchart TD`），其他示意图用 svg。

## 8. 文档工具

智能体可在沙箱内创建、修改、转换文档（Word / Excel / PPT 用 Python 库，格式转换与 PDF 用 LibreOffice）。
转换目标：`pdf`、`docx`、`xlsx`、`pptx`、`csv`、`txt`、`odt`、`ods`、`odp`、`html`。

- 工具依赖沙箱内的 LibreOffice、poppler-utils、中文字体与 Python 文档库，不来自 `npm ci`。容器启动后控制面在后台安装缺失部分
  （新环境约一两分钟），并把文档 skill 写给 Codex 与 Claude Code。安装失败时界面如实显示未就绪，owner 可点「安装/修复」重试。详见[运行手册](RUNBOOK.md#沙箱文档工具)。
- 所有解析与转换在沙箱内进行，控制面只以固定 argv 调用固定命令。路径先经工作区范围校验（拒绝越界、symlink 逃逸、选项注入）；
  预览均需鉴权；音视频保留 Range / 206 / 416 语义；主动内容一律以 `attachment` 下载。转换结果写成新文件，不覆盖原件。
- iPhone / iPad 添加到主屏幕的 web app 里，下载会让文件盖住整个应用且无法返回，所以那里的「下载」（文件卡片、预览、工作区、SVG/Mermaid 图）改为取回文件后打开系统分享面板（可「存储图像」「存储到文件」），应用停在原处；取回太慢使点按失效时，底部提示条再点一次「保存」即可。浏览器标签页里仍是普通下载。

## 9. 定时任务与每日推送

在主会话里直接说时间和要做的事，例如「每天早上 8 点查天气提醒我带伞」「每 2 小时看一下这个商品降价没」「帮我盯 10/6 Prime Day」。
定时任务属于账号，保存在控制面，与创建它的会话无关；每次运行是一个新任务。

- **规则**：派单器给出 `schedule`：`once` / `daily` / `weekly` / `monthly` / `interval` / `dates`，可带 `maxRuns` 或 `until`，以及每次要做的 `instruction`。
  一天多次用 `times: ["08:00","18:00"]`（最多 12 个）；不规律时间用 `dates`（最多 60 个）。服务端按 `PA_BROWSER_TIMEZONE` 校验并算出下次运行时间，
  规则无效时交回派单器重答。「帮我盯着…」「到时候提醒我…」类请求也按定时处理，节奏不明显时先给出可选项。说「现在先做一次」时本次照常执行。
- **执行会话工具**：每个账号的执行会话注册 MCP 服务 `aio_schedule`（成员网关 `/schedule/<运行时令牌>/mcp`，只通向本账号）：
  `schedule_create`、`schedule_list`、`schedule_change`（暂停 / 恢复 / 取消）、`schedule_update`（原地修改），校验与上限同派单器；
  Claude Code 自带的会话内计时工具
  （`CronCreate`、`CronDelete`、`CronList`、`ScheduleWakeup`）在执行轮次中禁用。循环间隔至少 15 分钟，每账号最多 20 个进行中的定时任务。
- **运行**：控制面每 30 秒检查到点任务，直接建一个已派好的任务（不经派单路由），附上次结果作为背景；执行会话被告知用户不在场，
  不提问、不再建定时任务。上一次未结束时跳过本次；停机期间错过的只补跑一次。结果显示为「定时任务「…」自动运行」。
- **管理**：侧栏「定时任务」页可修改、暂停、恢复、立即运行、删除（`PATCH /api/schedules/:id`、`POST /api/schedules/:id/:action`）；
  也可在主会话中说「暂停天气提醒」，派单器给出 `scheduleAction`。修改规则后 `maxRuns` 重新计数；已结束的任务改出新时间会重新开始，暂停的保持暂停。
  删除不影响已有运行结果。

### 每日推送

`PA_DAILY_FEED=1`（默认）时每个账号内置一个「每日推送」：owner 08:00 运行，成员依次错开 4 分钟（时段记在主库 `meta` 的 `feed_slot:<账号>`）。
时间按该账号**最近一次登录时浏览器所在的时区**（密码登录、注册与 Google 登录都由页面报告 `Intl` 时区，非法值忽略）：换了时区登录，推送改在新时区的同一时刻，
下次运行随之重算（暂停中的保持暂停）；从未带时区登录过的账号沿用部署时区 `PA_BROWSER_TIMEZONE`。只有每日推送跟随登录时区，其他定时任务仍按部署时区。
只有过去 24 小时内用户发过消息才运行，否则静默跳过（手动「立即运行一次」不受限）。

- **内容**：执行会话拿到用户最近 7 天的任务记录（最新 60 条含摘要，更早的只列日期与标题，最多 800 条）和最近 14 次推送话题，挑出今天值得
  提醒的 3–8 件事，分两类：关注事项的变化（价格、订单、日期、待回复的邮件，没变化的不写），以及从近期 2–4 个兴趣延伸出的新内容
  （问过老电影就推同类经典和正版观看处，问过做菜就推应季做法，问过宝宝辅食就推该月龄的下一步，并注明由哪次提问而来）；都要实际上网核实并附来源
  （推送轮不受通用执行约束中「控制工作量」的限制）。邮箱、订单和价格只算一类线索；很多用户只问日常问题、不跟踪任何东西，对他们推送就由新内容组成。
  新任务体现的兴趣优先；同一话题连推 3 次而无相关新任务时停推。关注事项没变化不算没内容，只有记录里找不到任何线索时才只回一句、不发通知；
  有内容时以手机通知推送「今日为你留意」。话题记入 `feed_history`，结果中的机器标记（`<!--feed-topics: …-->`、`<!--feed-empty-->`）不显示。
- **只读浏览**：可以打开用户已登录或任务中用过的网站（邮箱、订单、账单、关注动态），但严格只读：不发送、回复、点赞、购买、删除、
  改设置；不点开未读邮件与私信；未登录的网站跳过。
- **用户调整**：`aio_schedule` 的 `feed_get` / `feed_update` 可修改用户要求（`schedules.instruction`，不能突破只读规则）、推送时间，
  以及 `feed_memory` 中的 `care` / `avoid` / `note`（每类最多 30 条）。推送根据用户后续任务与对推送的直接回复，用 `feed_update`（`source: "feed"`）自行记录，每次最多改 3 条；用户在对话中给出的反馈由执行会话记下。
  「定时任务」页在推送卡片上显示「你的要求」和记住的条目。规划不会把「改推送」当成新的定时任务，内置推送只能用 `feed_update` 修改。
  内置推送可以暂停、恢复，不能删除；在主会话说「别再推了」会暂停它。

## 10. 语音输入

主会话输入区的麦克风按钮：点一下开始，再点一下停止（最长一分钟），识别文字追加到草稿，不自动发送。所有账号可用。

- **开启**：`PA_ASR_URL` 指向语音识别服务（`POST` 16 位单声道 WAV，返回 `{text}`，可选 `model`、`words`），例如 muse-gadget-sdk 的 `tts-server`
  （X-ASR 中英双语模型，常用词表作热词；请求 `/asr?punct=1` 时加标点并去掉口头禅，只有口头禅时返回空，按钮提示「没听清」）。未配置时 `GET /api/asr` 返回 `{enabled:false}`，按钮不显示。
- **语言**：`GET /api/asr` 同时返回识别服务能听懂的界面语言 `locales`（X-ASR 听普通话和英语，不支持西班牙语，因此是 `zh-CN`、`zh-TW`、`en`；见 `src/control/http/api.ts` 的 `ASR_LOCALES`）。界面语言（配置页选择或跟随系统）不在其中时不显示麦克风；旧控制面不返回该字段时照常显示。
  现有部署复用语音配件的识别服务：`PA_ASR_URL=http://192.168.1.118:4910/asr?punct=1`（old-mb）。
- **麦克风**：手机和平板（iOS/Android，含网页与 App）上始终用机身麦克风，连着蓝牙、有线或 USB 耳机也不用它们的麦克风：网页只能看到设备名，
  Android（Chrome/WebView）取「Speakerphone」，没有再取「Headset earpiece」，iOS 取名字含 iPhone/iPad 的那个；第一次录音先按默认打开（授权后才看得到名字），
  若不是机身麦克风就换成它（`deviceId: exact`），并把它记在本机（localStorage `voice.builtInMicrophone`），之后直接打开；找不到或打不开时退回系统默认。桌面不变。
- **链路**：浏览器取麦克风原始采样，降到 16 kHz 编为 WAV，经 `POST /api/asr`（JSON `{audioBase64}`，带 CSRF）交给控制面转发；
  识别出的文字再经与语音键盘同一套润色（`PA_DICTATION_MODEL`，owner 的 Claude 凭据，见「语音配件」）后返回 `{text, polished}`；
  识别服务返回的 `words`（它的常用词表）一并交给润色，用来改回它仍听错的品牌、地名等，
  润色失败或未配置 Claude 凭据时返回原文（`polished:false`）。录音不进沙箱；默认不落盘。
- **回测日志**：`PA_VOICE_LOG_USERS` 列出的账号（`*` 为全部）每次语音输入在控制面数据目录 `voice-log/<日期>/` 留下录音 WAV 和同名 JSON
  （录音用的麦克风名、当时可见的全部麦克风与音频硬件采样率——蓝牙或车载麦克风通常是 16/24 kHz、手机机身麦克风是 48 kHz；识别服务地址与其报告的模型、识别原文 `text`/`raw`、润色模型/effort/结果、各段耗时、错误），文件 0600，超过 `PA_VOICE_LOG_DAYS` 天（默认 30）的日期目录在新的一天第一次写入时删除。
  `node bin/voice-replay.mjs`（compose：`docker exec aio-control-1 node bin/voice-replay.mjs`）把这些录音重新送去识别：`--asr <地址>` 可给多个做对比，
  `--since/--until/--user/--limit` 筛选，`--polish` 同时跑润色，`--out` 写 JSON 报告；在某条 JSON 里加 `"expected": "<正确文字>"` 后，报告给出该条与总体的字错率（CER，忽略大小写、标点和空格）。超过 2 MB 返回 413，非 WAV 返回 400，识别服务出错或 30 秒无应答返回 502。
- **权限**：浏览器首次询问麦克风权限；App 声明了 iOS `NSMicrophoneUsageDescription` 与 Android `RECORD_AUDIO`。

## 11. 语音配件

桌面语音配件（如刷了 Muse Gadget 固件的 M5Stack CoreS3）把按住说话的内容发进一个账号：配件负责转写与朗读，只与服务端交换文字。

- **开启**：在控制面数据目录建 `gadget-token.env`（compose 为 `/data/gadget-token.env`，`PA_GADGET_TOKEN_PATH` 可改），内容
  `AIO_GADGET_TOKEN=<长随机串>`，权限 600。文件不存在时接口一律 401；令牌每次请求重新读取，更换无需重启。
- **绑定账号**：同一文件写 `AIO_GADGET_USER=<用户名>` 时，配件在该账号内执行（其环境、模型与知识库授权），owner 主会话看不到；
  用户名无效时 401；不写时代表 owner。现有部署绑定专用成员账号 `betaw`（`gpt-6.1-sol` / `low`，知识库可读写）。
- **接口**：`POST /api/gadget/messages`（`Authorization: Bearer <令牌>`，JSON `{text, clientMessageId}`）返回 202 `{id, status, done, reply, error}`；
  之后轮询 `GET /api/gadget/messages/<id>`，可带 `?wait=N`（最多 25 秒）长轮询。同一 `clientMessageId` 重发得到同一任务。不使用 cookie，因此不检查 CSRF。
- **执行**：不经派单器，直接建已派好的任务。代表 owner 时推理强度固定 medium，代表成员时用其分配的模型与推理强度。所有配件消息共用一个执行会话，
  回答按朗读要求输出（纯文本口语、一到三句、不用 Markdown、不追问）。问到其他任务时，执行会话用 `aio_history` 的 `history_search` / `history_get` 自行查询。
  每条消息是主会话中描述为「来自语音配件」的任务，完成时不发手机通知。
- **后台压缩**：共用会话某轮结束后上下文超过窗口 80%，且之后静默 3 分钟，控制面在后台执行一次 Codex 压缩（`thread/compact/start`）；
  压缩不进会话记录，期间到达的消息排在其后；沙箱休眠时不为此唤醒，Claude Code 会话不压缩。
- **用量页**：`GET /api/gadget/usage` 把 `PA_GADGET_USAGE_URL` 的 JSON 原样转给配件（5 秒超时、限 64 KB、非 JSON 返回 502；未配置 404）。
  现有部署指向 Usage HUD 的回环快照 `http://host.docker.internal:4796/gadget.json`，配件「用量」页每分钟拉取一次。
- **语音键盘**：配件「语音键盘」页点麦克风开始录音、再点一下结束；转写后发 `POST /api/gadget/dictation`（配件令牌，JSON `{text}`，最多 4000 字），
  控制面用 owner 的 Claude 凭据调 `PA_DICTATION_MODEL`（默认 `claude-sonnet-5-5`、effort `low`，10 秒超时；输入区语音输入共用）去赘词、改错字、补标点，
  再交给宿主 Mac 上的键盘桥（`bin/keyboard-bridge.mjs`）粘贴到当前光标处，返回 `{text, polished}`。
  说话的账号能用知识库（owner 与 `PA_KB_MCP_MEMBERS`）时，润色还会参考知识库里照片标注的人名（出现至少 10 次的，最多 40 个；
  经 `kb_sql` 读取，每 6 小时重读，读不到时 5 分钟后再试、照常润色），把被识别成同音字或拼错的人名改回原写法；其他账号不注入。润色失败时照原文输入（`polished:false`）；
  Mac 未授予辅助功能 409 `not_trusted`，桥连不上 502，未配置 `PA_KEYBOARD_BRIDGE_URL` 404。键盘桥只经这个接口触达，沙箱与执行器都用不到它；
  粘贴后剪贴板恢复原样，且标记为临时内容，剪贴板历史工具不记录。
- **固件无线升级**：`GET /api/gadget/firmware` 返回当前固件信息（版本、构建时间、大小、`elfSha256`），`GET /api/gadget/firmware.bin` 下载镜像；
  未发布时 404。发布：`node bin/publish-gadget-firmware.mjs <文件>`（compose 下先 `docker cp` 进控制面容器），校验后替换到 `PA_GADGET_FIRMWARE_DIR`。
  配件每 10 分钟检查一次，空闲时下载到另一分区并重启，新固件连不上会自动回滚。
- **owner 查看**：配件绑定成员账号时，owner 侧栏出现以该账号命名的入口（`/u/owner/gadget`），只读显示配件对话记录
  （`GET /api/gadget/history?limit=&before=`，成员访问 403）。

## 12. 出图（aio_image）

在主会话说「画一张…」「把这张图背景换成…」即可。每个账号的执行会话注册 MCP 服务 `aio_image`（成员网关 `/image/<运行时令牌>/mcp`，只写本账号工作区），
工具 `image_generate`：

- **参数**：`prompt`；`path`（工作区内 `.png`，默认存入 `workspace/images/`）；`reference_paths`（工作区图片，最多 5 张，不支持 SVG）；
  可选 `transparent_background`、`size`（auto / 1024x1024 / 1536x1024 / 1024x1536）、`quality`。
- **实现**：控制面用自己的 ChatGPT 登录调用出图接口（`gpt-image-2`，`/images/generations` 或 `/images/edits`），把 PNG 写进该账号工作区。
  登录只在宿主侧使用。成员的 Codex 走成员网关、没有内置 imagegen，因此用此工具代替。
- 仅在控制面有 ChatGPT 登录时提供（`PA_HOST_CODEX=on`），使用 owner 的 ChatGPT 套餐额度，所有账号共用，不设调用限额。
- **以文字和排版为主的图**（表格、日程、辅食/学习计划、清单、菜单、信息图）不用 `image_generate` 画或改：出图模型每次都重画所有像素，
  反复改字会越改越糊、字越改越错。执行器按沙箱 skill `aio-graphic` 写 HTML 页面（`tasks/<任务>/<名字>.html` + `assets/`），
  用 `~/.codex/tools/aio-graphic/aio-render.py` 以沙箱内无头 Chromium 渲染成 2 倍 PNG；改图就改 HTML 再渲染。
  `image_generate` 只画其中的插画素材，每张生成一次后重复使用。skill 与渲染脚本随沙箱启动写入（同分享 skill）。
- **真人照片修图**（修图、P 图、精修、专业修图、调亮调色、通透、天空过曝、磨皮、肤色、摄影棚效果、背景布平整、换背景）**不用** `image_generate`：它会把整张照片重画，
  脸、皮肤、手和头发变成"像但不是本人"，在 AI 结果上再改还会越改越失真、脸上出色块。执行器按所有账号内置的沙箱 skill `aio-photo` 处理，
  工具 `~/.codex/tools/aio-photo/aio-photo.py`（skill 与工具随沙箱启动写入，所有账号同一份；沙箱里改动 skill 会在下次启动时被覆盖，长期规则要改源码）：
  - **所有调色都用 LightCraft**（用户 2026-10-28 定：LightCraft 更好用，都用它；开源的 Lightroom 式照片冲印软件，固定 0.14.0，x86_64 / aarch64 两个 Linux 版本按 SHA-256 校验，装在工具目录 `lightcraft-0.14.0/`，
    约 110 MB 下载、210 MB 占用，后台随照片库一起安装，换版本时删掉旧目录）：`retouch` 默认从 LightCraft 自动设置开始（曝光、对比、高光、阴影、白、黑、自然饱和度；
    `--manual` 改为从原片出发），叠加
    `--look bright|clear|sky`（调亮 / 通透去灰 / 压回过曝天空并加深蓝色的起点）与可重复的 `--develop 控件=值`（LightCraft 的 122 个冲印控件，
    如 `light.shadows`、`effects.dehaze`、`mixer.orange.sat`、`detail.nrLuminance`；控件名先校验，不认识的由 LightCraft 拒绝）。
    `--exposure`（档）、`--warmth`（白平衡，±1 对应 ±2500 K）、`--contrast`、`--saturation` 也换算成 LightCraft 的相对调整（`develop.adjust`）叠在最后。
    LightCraft 对整张照片做同样的全局调整，脸上细节不变。只有 LightCraft 装不上时，skill 要求先告诉用户，用户仍要时才用 `--engine basic`
    （下面的查表调整，不支持自动、预设、控件和磨皮）并说明不是 LightCraft。
    2026-10-28 在 owner 沙箱实测：900 万像素约 1 秒（CPU），手机竖拍（EXIF 方向）照片方向与尺寸正确，人脸核对相似度 0.98–0.99。
  - **磨皮** `--soften 0..1`：同样的冲印再加一份降低纹理（`effects.texture = −60×soften`、`effects.clarity = −12×soften`）的版本，只按「人物抠图 × 肤色（YCrCb）」
    的柔边蒙版混入 80%，眼睛、眉毛、嘴唇、头发、衣服和背景保持原样清晰；skill 建议 0.3–0.5、宝宝 0.2–0.3、不超过 0.7。实测全图降纹理 −70 会把眉眼一起糊掉，
    而人脸核对仍有 0.93、拦不住，所以靠蒙版限制范围而不是靠核对。仍不做瘦脸、放大眼睛等改形。
  - `retouch <原片> -o <输出>`：每次都从原片开始；`--engine basic` 时，光影色彩（自动提亮人物中间调、曝光、冷暖、对比、饱和度）对每个像素做同一个查表变换，
    脸上的细节一点不变；`--background smooth`（把原背景布的褶皱熨平，保留颜色、光线过渡和柔和阴影，只适合纯色背景布）/
    `studio`（无缝摄影棚背景，默认暖奶油色 `#EEE5D8`，带脚下柔和投影）/ 一张背景图（如 `image_generate` 生成的空摄影棚背景）时，
    人物用 rembg 的人像模型（`u2net_human_seg`）从原片抠出，按原像素放回新背景前；`--subject any` 改为保留商品、宠物等主体。
    每次合成另存一张抠图预览（人物放在灰底上），并用 OpenCV YuNet 人脸检测核对抠图：有人脸没被抠进来、或抠到了头但身体被当成背景时给出警告，
    这时 skill 要求改用 `--background keep`（只调光影色彩）并如实告诉用户。
  - `check <原片> <成片>`：只在人脸框内部比较细节结构（高频纹理的归一化相关，光影和颜色的整体变化不影响），相似度低于 0.85 判为被重画，
    另存原片/成片人脸并排对比图；skill 要求交付前每张都过 `check`，不过就从原片重做，不交付、不说"没问题"。
  - skill 的其他规则：一张照片一条命令，不拿别的照片或其结果做参考；照片里的大人、抱宝宝的手、道具一律保留，不改构图；用户重发原片或说"再来/重新修"就从原片重做，
    不复制旧结果；只有空背景图、或用户明确要求改内容（过曝成纯白的天空换成 AI 蓝天、加减物体、换衣服、画成插画）时才用 `image_generate`，并说明哪部分是 AI 做的。
    输出里带本次的 `params` 与 `lightcraft`（自动选了什么、设了什么），追问「再亮一点」时只改用户说的那一项从原片重修。
  - **交付是修图前后对比**：skill 要求把结果放进 ```` ```compare ```` 块（`{"items":[{"before":原片,"after":成片,"title","note"}]}`，`retouch` 输出里的 `compare` 就是一项），
    多张一并放进同一块并另附 zip。控制台（`src/ui/src/compareBlocks.ts`、`components/PhotoCompare.tsx`）画成对比卡：默认显示成片，
    按住图片（鼠标按下、手指长按，或按住空格/回车）显示原片，松开回到成片；图上角标提示「按住看原图」，按住时变成「原图」；长按不弹系统菜单、不拖图、不选字，
    滑动页面或指针离开也会松开；「查看大图」用文件预览打开成片（可下载）。
    只认工作区图片，两张都经图片缓存加载、接近屏幕才取（原片先载好，按下不闪白）。卡片在主会话的消息预览里时，按住不会打开整条消息。
    对比图像消息里的图片一样不加外框、高度不超过 420 像素（且不超过屏高 60%），宽度随照片比例收窄、标题与按钮贴齐照片边缘；载入前先占正方形，竖图载入后不把消息往下顶太多。
  - 依赖装在工具自己的 venv（`rembg==2.0.69`、`onnxruntime==1.23.2`、`opencv-python-headless` 4.x，均为仍支持沙箱 Python 3.10 的版本），
    抠图与人脸模型存在工具目录（人脸模型按固定提交下载并校验 SHA-256）；控制面每次启动后在后台安装（排在行情库之后，一次只装一个），
    首次约一两分钟，之后只读戳记。抠图在长边 2048 像素的副本上于独立子进程运行（模型约 1 GB 内存随进程退出释放），合成按行分块，
    2400 万像素的照片约 3 秒、峰值约 1.25 GB。

## 12a. 朗读（aio_tts）

在主会话说「把这段读出来」「做成语音」即可。设置 `PA_TTS_URL` 后，每个账号的执行会话注册 MCP 服务 `aio_tts`（成员网关 `/tts/<运行时令牌>/mcp`，只写本账号工作区），
工具 `text_to_speech`：

- **参数**：`text`（一次最多 1500 字）；`path`（工作区内 `.wav`，默认存入 `workspace/audio/`）；可选 `voice`（模型的 9 个预置音色：
  vivian、serena、uncle_fu、dylan、eric 讲中文，ryan、aiden 讲英文，ono_anna 日文，sohee 韩文）与 `language`（中、英、日、韩、德、法、俄、葡、西、意）。
  不给语言时按文字判断（有汉字为中文，假名为日文，韩文字母为韩文，其余英文），不给音色时按语言选默认音色。方括号是控制标记（`[pause:500ms]` 停顿）。
- **实现**：所有账号共用一台语音服务：Qwen3-TTS 12Hz 0.6B CustomVoice，INT8 量化、CPU 推理（纯 C 引擎 qwen3-tts 的 `--serve`，`POST /v1/tts`
  收 `{text, speaker, language}`、回 24 kHz 16 位单声道 WAV；任何同样契约的服务都可替换）。控制面按句切成不超过 120 字的段（服务端单次生成 60 秒音频封顶，120 字中文约 27 秒）依次请求，拼成一个 WAV
  写进该账号工作区；沙箱本身不接触语音服务。服务比实时慢（old-mb 上约 1.45 倍：120 字中文 39 秒），控制面同一时间只送一个请求，其他账号的请求排队等候（工具超时 20 分钟）。
- **展示**：执行器把文件写成单独一行的链接 `[说明](路径)`，消息里显示为播放器（见「富内容块」）；要 mp3 或更长的音频由执行器在沙箱里用 ffmpeg 转换、拼接。
- 现有部署：语音服务在 old-mb（`PA_TTS_URL=http://192.168.1.118:4911/v1/tts`），部署与排障见 [运行手册](RUNBOOK.md)「朗读服务」。

## 14. 外部集成

以下集成都只经成员模型网关按账号转发，凭据只留在宿主进程，沙箱只拿到各自运行时的能力地址。新增网关 MCP 必须同时写入沙箱 Codex 的
受管策略 `/etc/codex/requirements.toml`，否则 Codex 会停用该线程级服务。

### Jev 决策

Jev（TypeSafe System One）根据状态和选项返回选择、各选项概率与置信度。key 从 `PA_JEV_SECRETS_FILE`（默认 `~/.config/aio-agent/jev.env`，
权限须为 600 / 400；环境变量 `TYPESAFE_API_KEY` 优先）读取。所有账号共用，用于：

- **派单评分**：见[派单与历史召回](#2-派单与历史召回)。
- **`decide` 工具**：执行会话注册 MCP 服务 `aio_decision`（成员网关 `/decision/<运行时令牌>/mcp`），参数 `question`、`options`
  （id → 含义，2–20 个）、可选 `context` 与 `rules`。每次调用的账号、问题、选项数、选择、置信度、耗时与用量记入宿主库 `decision_events`，不设限额。

没有 key 时两项都不出现。

### 知识库

设置 `PA_KB_MCP_URL`（宿主上的 streamable HTTP MCP 服务）后：

- **授权**：owner 及 `PA_KB_MCP_MEMBERS` 列出的成员可用，名单在重启时生效，移出名单后原地址返回 403。
- **接入**：获准账号的执行会话注册 `aio_kb`（成员网关 `/kb/<运行时令牌>/mcp`）。网关转发时附加 `Authorization: Bearer <令牌>` 与
  `X-Aio-User: <用户名>`。上游令牌从 `PA_KB_MCP_SECRETS_FILE`（环境变量 `KB_MCP_TOKEN` 优先）读取，缺失时不提供此功能。
- **隔离**：上游应只监听 loopback 并校验令牌；受管策略只为获准运行时放行这一条地址。上游不可达时工具调用返回 502，不影响任务其他部分。
  网关不缓存、不落库任何内容。给什么内容完全由上游决定，上游应只读并只提供这些账号可见的内容。
- **超时**：单次调用最多等 90 秒（扫描件要先做文字识别，十几页约 15 秒）。
- **现有部署**：上游是 aio-db-kb 的 `kb-mcp`（2026-10-12 起，SQLite），除整理过的页面外还以 `kb_source` 提供页面引用原件的文字（owner 与 `cr` 可读；扫描版 PDF 和图片由它在宿主上即时识别文字），并有 `kb_grep`（正文与原件全文正则）、`kb_refs`（引用与依赖关系）、`kb_sql`（只读 SQL）；网关不按工具名过滤，上游新增工具直接可用；
  执行会话只在需要时读原文，个人信息只引用回答所需部分。`KB_MCP_WRITERS`（现为 `betaw`、`owner`、`cr`）额外获得 `kb_note`：只在 workspace
  `raw/aio-notes/<用户名>/` 新建笔记，经知识库收录后才可检索。用户要求记录、或聊到家庭偏好与 Roy 的事项时，执行器先查重再主动记一条并告知用户。

### Home Assistant

设置 `PA_HA_MCP_URL`（如 `http://<HA 地址>:8124/api/mcp`，HA 官方 MCP Server 集成）后：

- **授权**：只有 `PA_HA_MCP_ACCOUNTS` 列出的用户名可用（owner 也需列出）。现有部署授权 `betaw`、`owner`、`cr`。
- **接入**：获准账号注册 `aio_ha`（成员网关 `/ha/<运行时令牌>/mcp`），网关附加 HA 长期访问令牌（`PA_HA_MCP_SECRETS_FILE` 中的 `HA_MCP_TOKEN`；
  compose 用 `AIO_SECRET_HA_MCP` 挂载）。
- **能力范围由 HA 决定**：只提供「暴露给 Assist」的实体，工具为 HA 意图（`HassTurnOn`、`HassLightSet`、`GetLiveContext` 等）。
  收窄设备范围在 HA 中修改暴露名单；收回授权可移出 `PA_HA_MCP_ACCOUNTS` 并重启，或在 HA 中删除令牌。
- 执行会话只操作用户本次要求的设备，操作后读一次状态确认。
- **历史**（`src/control/haHistory.ts`，同一 `aio_ha` 上追加的 `ha_history`，不经 HA 的 MCP Server，用同一令牌走 HA 的 WebSocket 接口）：
  按实体 id 或名称（精确名称优先，否则包含即匹配，最多 10 个）查一段本地时间（默认最近 24 小时）的变化。有长期统计的测量型传感器（温度、湿度等）
  返回每段的平均 / 最低 / 最高与整段高低点，粒度按时长自动选（≤6 小时 5 分钟、≤5 天每小时、≤120 天每天，再长每周，也可指定）；
  HA 的小时与天统计长期保留、5 分钟统计约 10 天，当前未结束的一段还没有统计，以「现在」的读数补上。其他实体（温控器、灯、开关、二元传感器）
  返回状态变化与各状态累计时长，温控器另按 `hvac_action` 统计加热 / 制冷 / 空闲时长（逐条记录约保留 10 天，取决于 HA recorder）。
  只读「暴露给 Assist」的实体，与 HA 自己的 MCP 工具同一范围；数值保持 HA 的单位。
- **看板备注**（`src/control/haDashboard.ts`）：HA 自己的工具只认集成给的名字（如 `H5100 2676 Temperature`），不知道它在哪个房间。
  控制面读 HA 全部看板的配置（`lovelace/config`），记下每个暴露给 Assist 的实体在卡片上的名字与位置（视图 › 标题 › 小标题，如
  `婴儿卧室 — 家 › 房间温湿度 › 温度`；同名而位置更笼统的徽章不重复），缓存 5 分钟，改看板后自动跟上。每次 `GetLiveContext` 的回答末尾附上这份
  对照表；`ha_history` 也按看板名字找实体（如直接查「婴儿卧室」），并在结果里标出。读不到看板时沿用上次的结果，从未读到则不附加，不影响 HA 原本的回答。
- **摄像头**（`src/control/camera.ts`，同一 `aio_ha` 上追加的工具，不经 HA 的 MCP Server，直接用同一令牌调 HA 的 REST / WebSocket / 媒体接口）：
  `camera_list`（各摄像头能力与录像范围）、`camera_snapshot`（当前画面，图片回给执行器）、`camera_ptz`（方向点按或预置位，转完回一张画面）、
  `camera_recordings`（连续录像覆盖范围、缺口与侦测事件）、`camera_recording_frames`（从录像某一时刻起取最多 6 张图）。
  录像、事件与云台按摄像头在 `PA_HA_CAMERAS` 声明：连续录像是 HA 媒体源里 `<名>_YYYY-MM-DD_HH-MM-SS.mp4` 的分片（fragmented MP4，
  控制面读分片尾部的索引（mfra），按 Range 只取初始化段和目标所在的两个分片交给 ffmpeg 解码，取一张约 0.1–2 秒；正在写的最后一片
  还没有索引，由 ffmpeg 经 HTTP 顺序读到该时刻），事件是
  `YYYY-MM-DD_HH-MM-SS_<标签>.mp4`；时间一律按控制面时区（`TZ`）的本地时间。云台调声明的集成的 `move`（x、y）与 `goto_preset`（name）服务。
- **摄像头卡片**：执行器在回复里写 ```` ```camera ```` 块（`{"camera": "<实体>"}` 为直播，加 `"at": "YYYY-MM-DD HH:MM:SS"` 为从该时刻回放）。
  直播先显示快照，点播放后经 `/api/cameras/hls/<令牌>/…` 转发 HA 的 LL-HLS（Safari/iOS 原生播放，其他浏览器按需加载 hls.js；
  只转发本进程发出的流令牌与 HLS 文件名）；声明了云台的摄像头在画面边缘有四个方向键。HA 只能给 WebRTC 的摄像头（Ring）在卡片里是每 10 秒刷新的快照。
  回放按 Range 转发录像分片，播完自动接下一片，标题显示画面对应的本地时间；卡片可在回放与直播间切换。
  卡片接口只对 `PA_HA_MCP_ACCOUNTS` 里的账号开放，其他账号看到「没有开通摄像头」。现有部署：C201（`camera.c201_go2rtc`，录像 `c201`、事件
  `local/c201-events`、云台 `tapo_ptz`）与三台 Ring（只有快照）。

### 打印机

设置 `PA_PRINTER_URI`（家里网络打印机的 IPP 地址，如 `ipps://192.168.1.123/ipp/print`；支持 IPP Everywhere / PWG raster 的打印机）后：

- **授权**：只有 `PA_PRINTER_ACCOUNTS` 列出的用户名可用（owner 也需列出）。现有部署授权 `owner` 与 `cr`。
- **接入**：获准账号注册 `aio_printer`（成员网关 `/printer/<运行时令牌>/mcp`），工具为 `printer_status`（状态、缺纸卡纸、墨量、纸张）
  与 `print_file`（工作区里的 PDF 或图片；可选页码、份数 1–20、单双面、黑白）。其他格式由执行会话先在沙箱里转成 PDF。
- **流程**：该账号自己的沙箱用 `pdftoppm` 把文件渲染成 300 dpi 的 PWG raster（`src/control/printer/scripts/pwg-raster.py`，需沙箱里的 numpy 与 Pillow），
  控制面取回后以 IPP Print-Job 发给打印机；纸张按打印机当前装的纸。一次最多 50 页，同一时间只发一个作业。沙箱本身不接触打印机。
- **诚实**：打印机已停止（缺纸、卡纸等）时拒绝并说明原因；发送途中连接中断时报告“不确定是否已收到”，不自动重发。
  `ipps://` 不校验打印机的自签名证书，打印机由配置的地址确定，地址应在路由器上固定（DHCP 保留）。

### 手机

Android 手机用 USB 接在装了 Mac App 的 Mac 上，由 App 运行的 `bin/phone-bridge.mjs`（只监听 loopback、要 App 给的桥接令牌）提供，
交给连接这台 Mac 的账号（owner 与成员相同）。控制面宿主不再直接接手机。

- **连接**：工作区「手机」里（在 Mac App 中打开）点「连接这台 Mac」。控制面为该账号签发设备令牌
  （`POST /api/device-links`，只返回一次，库里只存哈希），App 把它存在只有本机用户能读的文件里（`~/Library/Application Support/ai.clawpage.agent/device-link.json`，0600），
  首次使用时把手机组件装进同一目录（Node.js、mobile-mcp 与 ws 按 App 内锁文件 `npm ci`、scrcpy、adb；都是固定版本并校验 SHA-256，Mac 上已有 adb 就直接用），
  然后运行桥接。桥接主动连到 `wss://<主站>/api/device-link/connect`（`bin/device-link-client.mjs`），控制面把该账号的工具调用、状态、截图和实时画面经这条连接发给它；
  这条连接只放行桥接自己的入口（手机的 MCP、状态、截图、实时画面，以及浏览器的 MCP 与状态）。App 开着时手机可用；「手机」里列出该账号连过的 Mac，可随时移除，移除后连接立即断开、App 删掉令牌。
  一个账号连了多台 Mac 时用最近连上的那台。在浏览器里打开时「手机」只列出连过的 Mac 并说明要装 Mac App。
- **授权**：每个账号只有自己的手机。成员网关只给连过 Mac 的账号发手机令牌：连上第一台 Mac 时该账号新开的执行会话获得 `aio_phone`，
  移除最后一台后失去；`/api/phone` 与画面接口只返回本账号的手机，没有时返回“不可用”。
- **执行器工具**：`aio_phone`（成员网关 `/phone/<运行时令牌>/mcp`）。握手（`initialize`、工具列表）由网关回答，不依赖 Mac：Codex 每个线程只在开始时启动一次 MCP，
  Mac 恰好不在线也不会让这个线程永久失去手机；工具列表在 Mac 在线时取自 Mac，否则用 `src/control/phoneTools.ts` 里记录的同一份。
  工具调用经网关自己与该 Mac 上 mobile-mcp 的会话转发（mobile-mcp 重启丢了会话时重开一次）；Mac 不在线时调用返回工具错误，提示用户打开那台 Mac 上的 App。上游是 mobile-mcp（固定版本，关闭遥测），桥接只放行作用在手机本身的工具：
  列设备与应用、启动/关闭应用、点按/长按/双击/滑动、读屏幕元素、截图（只回给调用方）、按键、打开网址、输入文字、方向、手机剪贴板、批量执行。
  会读写 Mac 上文件的（存截图到路径、从本机路径装 APK、录屏、存日志）、卸载应用、改定位以及 mobile-mcp 的云手机工具一律拒绝，批量执行里的步骤同样过滤。
  中文等非 ASCII 输入需要手机上装 mobile-mcp 的 devicekit 辅助应用（`node phone-bridge.mjs devicekit`，App 尚未自动安装）。
- **实时画面**：工作区「手机」用 WebSocket `/api/phone/screen` 接收 scrcpy 的 H.264 画面，
  浏览器用 WebCodecs 解码（Safari 16.4+ / Chrome）。可直接点按、拖动、滚轮，下方有返回、主屏幕、最近应用、音量、电源键，
  文字框经手机剪贴板粘贴到当前输入框（支持中文，会覆盖手机剪贴板）。接口只接受主站来源（Origin）上本账号的会话，会话退出后断开；
  伴随站不提供，以免沙箱生成的页面借工作区 cookie 操作手机。没人看时桥接在 15 秒后停止编码；观看端跟不上时丢帧，追上后要一个关键帧，而不是积压。
- **任务卡片里的手机**：用过 `aio_phone` 的任务（执行记录里有它的工具调用），在执行中或等待补充时卡片显示一行手机横条，点开才显示手机截图（`/api/phone/screenshot`，
  桥接 `screencap`，macOS 上用 `sips` 压成 JPEG；展开时每 10 秒刷新，收起不截图），点截图或「去手机操作」弹出可操作的实时画面；等待补充时另有「完成，继续」，
  替用户回复“已在手机上操作完成”，执行会话读屏确认后继续。
- 执行会话操作手机时，用户能实时看到；付款、发消息、删除这类步骤先确认。用户让它读取本机短信验证码时它可以读取并填写（仅用于这次要登录的账号），
  登录/支付密码、指纹人脸由用户本人在卡片的手机画面里完成。

### Mac 上的浏览器

连手机的同一条 Mac 连接还提供那台 Mac 上一个 AI 专用的 Google Chrome，由同一个 `bin/phone-bridge.mjs` 经 `bin/user-browser.mjs`
启动并运行 chrome-devtools-mcp（固定版本，关闭使用统计、CrUX 与更新检查；`--browserUrl` 连到这个 Chrome）。它和沙箱浏览器（`aio_tabs`）并存，不替代它。

- **专用配置，不弹窗**：桥接用 Mac 上已安装的 Google Chrome，以独立配置（App 数据目录 `ai.clawpage.agent/phone/ai-chrome`）启动：
  `--headless=new`、`--remote-debugging-port=0`（只听 loopback）。Chrome 只对用户自己的默认配置要求在 `chrome://inspect` 打开远程调试并逐次点「允许」，
  专用配置不需要，所以从不弹窗；它也碰不到用户自己的 Chrome、标签页和登录。网站在这里登录一次（通常是执行会话 `request_human` 时用户接管完成）就一直保留在这个配置里。
- **不影响用户使用 Mac**：无头运行，没有窗口和 Dock 图标，不抢焦点、鼠标和键盘，显示器休眠时也照常渲染。画面靠 CDP 推流给控制台（像 OBS 抓一个不在前台的窗口）。
  为了不像机器人：UA 去掉 `HeadlessChrome`（按 Chrome 的 Info.plist 大版本号写成桌面 Chrome 的 UA）、`--disable-blink-features=AutomationControlled`（`navigator.webdriver` 为 false）、
  语言跟随 Mac 的系统首选语言（`--lang` / `--accept-lang`）、关掉后台节流。2026-10-18 在本机验证：Cloudflare 勾选框可点过、Google 登录页正常、Cookie 重启后保留。
  评估过的其他做法：有界面的 Chrome 放到虚拟显示器（CGVirtualDisplay）上，在显示器休眠时它会变成主屏、牵动用户的窗口；移出屏幕时 macOS 总会留约 40 像素且启动会抢焦点；
  最小化或隐藏后 Chrome 停止渲染、截图超时。所以选无头。
- **生命周期**：第一次工具调用时启动（握手与工具列表不需要它）；还在运行的旧实例（例如 App 重启后）直接接管；崩溃后下次调用重新启动；桥接退出时关闭。
  启动前删掉配置里残留的 `DevToolsActivePort`，以免把已退出的 Chrome 的端口当成新的。Mac 没装 Chrome 或启动失败时，工具返回写明「改用沙箱浏览器」的错误。
- **每个页面一个窗口**：`new_page` 由桥接自己用 CDP 建一个新窗口（1280×800，后台）再导航，不用 chrome-devtools-mcp 的新标签页：标签页在别的任务的页面切到前面时会停止渲染。
  智能体的 `select_page` 一律不带到前台；`new_page` 的 `background`、`isolatedContext` 参数不提供。
- **授权**：与手机相同，只给连过 Mac 的账号（成员网关 `/user-browser/<运行时令牌>/mcp`，执行器里叫 `aio_user_browser`），连上第一台 Mac 时获得、移除最后一台后失去。
  握手与工具列表由网关回答（Mac 不在线时用 `src/control/userBrowserTools.ts` 里记录的一份），线程开始时 Mac 不在线也不会丢掉它。
- **优先与回退**：执行会话先调 `list_pages`；Mac 不在线、没装 Chrome、或 Mac 上的 App 旧到没有浏览器时，工具立即返回写明「改用沙箱浏览器（aio_tabs）」的错误，
  执行会话在本任务余下部分改用 `aio_tabs`，并在回复里说一句。要上传或下载工作区文件、或用户指定沙箱浏览器时直接用 `aio_tabs`。
- **只放行作用在浏览器里的工具**：列/开/切/关页面、导航（只允许 http(s) 与 `about:blank`，挡 `file://`、`chrome://` 等）、读页面结构、截图（只回给调用方）、
  等待、点击、悬停、填写、表单、输入、按键、拖动、对话框、页面内脚本、控制台与网络请求。上传文件、任何带文件路径的参数（存截图/快照/脚本结果/请求体到路径）、
  模拟设备与改窗口大小、性能追踪、Lighthouse、堆快照一律拒绝，工具描述里也去掉这些参数。
- 执行会话用 `new_page` 开自己的页面并带 `pageId` 操作，不动别的任务的页面，用完关掉自己开的页面；付款、下单、发消息、删除、改账号设置前先确认。
  沙箱浏览器的密码器（`browser_login`）只在 `aio_tabs`。同一账号的多个任务共用这一个 Chrome；除了被接管的页面，页面归属靠执行规则约束，不像 `aio_tabs` 那样由服务强制。
- **工作区「Mac 浏览器」**：列出这个 Chrome 里打开的全部页面（`GET /api/user-browser/pages`，经 Mac 的 `list_pages`，Chrome 自己那个空白页不列），
  标出是谁的：任务的页面（任务标题，AI 在用 / 你在操作）、你在这里打开的（「你的」）、其他（例如登录弹窗）。选中一个即看实时画面（WebSocket `/api/user-browser/screen?page=<页面号>`）。
  地址栏打开你自己的页面（`POST /api/user-browser/pages`，只收 http(s)，没写协议补 https），用来先把 AI 要用的网站登录好；你的页面和「其他」页面直接可操作、可关闭
  （`DELETE /api/user-browser/pages/<页面号>`），任务的页面只能看，点「接管」（与任务卡片同一个接口）后才能操作、不能在这里关闭。你打开的页面只记在控制面内存里，重启后显示为「其他」。
  没连 Mac 时提示去「手机」连接；Mac 不在线或没装 Chrome 时说明原因。接口版本因此升到 6（`src/common/version.ts`）。
- **任务卡片上的预览与接管**：每次调用都带任务身份（与 `aio_tabs` 相同的 `X-AIO-Task`，即执行会话），网关据此记住每个任务在用的页面（`new_page` 开出的、或调用里的 `pageId`；
  只存在控制面内存里，重启或 Chrome 重启后要等任务再用一次）。用过的任务卡片上有一行「AI Chrome」：谁在操作、页面地址，点开才截图
  （`/api/tasks/<id>/user-browser/screenshot`，经 Mac 的桥接截那个页面），执行中每 10 秒刷新。
  - 「接管」（`POST /api/tasks/<id>/user-browser/control`）挡住 AI：这个任务除 `list_pages` 外的调用都返回“用户已接管，请用 request_human 等待”；
    「交还给 AI」恢复。网关自己的工具 `request_human`（不经 Mac）让执行会话请用户做一步（登录、验证码、两步验证、支付信息、最后确认）：卡片显示原因，调用一直等到用户交还（最长 30 分钟，
    所以这个服务的工具超时与 `aio_tabs` 同为 31 分钟），然后执行会话重新读页面再继续。卡片上的「完成，继续」就是交还。
  - **实时画面**：卡片或预览点开是那个页面的实时画面（WebSocket `/api/user-browser/screen?key=<执行会话>`，只认主站来源上本账号的会话）。
    桥接用自己的一条 CDP 连接对那个页面 `Page.startScreencast`（JPEG 画质 55，最长边 1600）：页面有变化才出新帧，最多每秒 8 帧，前一帧发走后才确认下一帧（慢的观看端少收帧、不积压）；控制台用画布绘制。
    接管后才能操作，输入由桥接经 CDP 直接发给页面：点按、按住拖动（`Input.dispatchMouseEvent`）、两个方向的滚轮（滚指针下的区域）、按键与编辑快捷键（全选/撤销/重做/剪切/复制）、
    输入文字（`Input.insertText`，支持中文）、后退/前进/刷新。没接管时控制面丢弃一切输入。坐标按画面比例换算成页面视口的 CSS 像素。
  - **手势**（与沙箱桌面相同，`src/ui/src/components/RemoteStage.tsx`）：点按＝点击（等 280 毫秒确认不是双击）、单指拖动先平移放大的画面、到边后滚动页面（带惯性）、
    双指捏合缩放并平移（1～5 倍，只缩放本地画面）、双击放大到 2.5 倍或还原、长按 0.45 秒后拖动＝按住左键拖拽、双指轻点＝右键。
    手机上默认 1.3 倍屏宽、居中。电脑上（Mac App）鼠标就是鼠标：按下/移动/松开、悬停、滚轮滚页面，触控板捏合缩放画面；点一下画面后键盘直接输入到页面（含输入法与粘贴）。

### Mac 上的终端

同一条 Mac 连接还可以提供那台 Mac 的终端（`aio_mac_shell`），像 pi 一样只有四个工具：`read`、`write`、`edit`、`bash`。
由同一个 `bin/phone-bridge.mjs` 经 `bin/mac-shell.mjs` 提供（`POST /shell/mcp`、`GET /shell/status`），控制面 `src/control/macShell.ts` 经成员网关 `/mac-shell/<运行时令牌>/mcp` 转发。

- **工作区「Mac 终端」**：单独的一个应用（图标是带提示符的笔记本电脑，与沙箱的「终端」分开），显示连接的 Mac 的终端状态：没连 Mac（带「去连接 Mac」，转到「手机」）、Mac 不在线、Mac 上的 App 太旧、已打开或已关闭，Mac 没装 tmux 时另有提示。
  状态来自 `GET /api/mac-shell/status`（经设备连接问 Mac 的 `GET /shell/status`，只回本账号的 Mac；接口版本因此升到 10，`src/common/version.ts`），打开时每 4 秒刷新。
- **默认关闭，只能在那台 Mac 上打开**：开关「允许 AI 使用这台 Mac 的终端」只出现在「Mac 终端」里，而且只在 Mac App 内、这台 Mac 持有的是本账号的连接时（别的账号连的 Mac、网页版、手机上都只显示状态）。
  选择存在 App 数据目录的 `device-link.json`（与设备令牌同一个 0600 文件），App 以 `PA_MAC_SHELL=1` 重启桥接才生效；控制面、网页版和别的设备都改不了它。
  关着时调用返回“终端没打开，请用户在那台 Mac 的 App 里打开，或改在沙箱里做”。旧版 App 不报告这个开关，控制台就不显示它，调用返回“Mac 没有应答（App 可能需要更新），结果未知”。
- **授权**：与手机、Mac 浏览器相同，只给连过 Mac 的账号，连上第一台 Mac 时获得、移除最后一台后失去；握手和工具列表由网关回答（定义在 `src/control/macShell.ts`），Mac 不在线也不会让线程丢掉它。
  它和用户本人一样有这台 Mac 的权限：执行规则要求删除或覆盖不是自己创建的文件、改系统或应用设置、装卸软件、sudo、把数据发出 Mac 之前先确认，不主动读密钥类文件。
- **bash 跑在 tmux 里**：专用的 tmux 服务器（socket `aio-agent`，`-f /dev/null` 不读用户的 tmux.conf），每个任务一个会话 `aio-<执行会话>`（不带任务身份的调用共用 `aio-main`），
  所以 `cd` 和 `export` 在同一任务的多次调用之间保留。每次调用把命令写进会话目录（`$TMPDIR/aio-mac-shell/<会话>/`，0700）再在会话里 source，
  输出写文件、退出码写文件；标准输入是 `/dev/null`（等输入的命令会一直等到超时）。返回最后 2000 行或 50 KB，被截掉时写明完整输出的文件路径。
  超时默认 120 秒、最长 240 秒（设备连接用 fetch 转发，它等应答最多 300 秒）：到时发 Ctrl-C，停不下来就重建会话；命令自己 `exit` 了，下次调用开新 shell。
  上一次的命令还在跑（例如网关那头断了）时，下一次先 Ctrl-C、不行就重建，并在输出里说明。用户可以 `tmux -L aio-agent attach -t aio-<…>` 旁观（只看到命令和输出的末尾）。
- **干净的环境**：shell 只继承用户名、HOME、语言、TMPDIR 和 PATH，桥接自己的令牌（`PHONE_BRIDGE_TOKEN`、`PA_DEVICE_LINK_TOKEN`）不进去；
  没有语言设置时补 `en_US.UTF-8`；PATH 先放 Homebrew（`/opt/homebrew`、`/usr/local`），再跑 `path_helper`；不读用户的 shell 配置，`PAGER`/`GIT_PAGER` 为 `cat`，历史记录写在会话目录里。
  Mac 上没有 tmux 时 `bash` 返回“请安装 tmux（brew install tmux）”，另外三个工具照常可用（`PA_TMUX` 可指定 tmux 路径）。
- **文件工具**：路径可以是绝对路径、`~/…`，或相对于这个任务的 shell 当前目录（还没有 shell 时是用户主目录）。`read` 文本每次最多 2000 行或 50 KB（`offset`/`limit` 续读），
  二进制文件拒绝，png/jpg/gif/webp 以图片返回（大于 1 MB 用 `sips` 缩成 JPEG）；`write` 整体写入并建目录；`edit` 用 `edits[]` 做精确替换，每段 `oldText` 必须唯一且互不重叠，
  任何一段不匹配就整个不写，保留文件原有的 CRLF 和 BOM。同一文件的写入串行，同一会话的命令串行。
- **生命周期**：六小时没用过的会话连同目录一起删掉；桥接退出（App 退出、关掉终端开关、移除连接）时整个 tmux 服务器随之结束，在跑的命令也会结束，要长跑的放后台（`nohup … &`）。

### Clawpages（可分享、可存数据的页面）

沙箱内置 `clawpages` skill（原名 `aio-share`，重新播种时删除旧目录），Codex 与 Claude Code 两个执行器都装：智能体把页面目录
（`/home/gem/workspace/share/<页面名>/`，入口 `index.html`）用 `python3 /home/gem/.codex/tools/aio-share/aio-share.py publish <目录>`
发布，得到公开地址 `https://<工作区域名>/u/<用户名>/share/<页面名>/`（短地址 `/u/<用户名>/share?<页面名>`）。页面本身只有公开模式；
数据按表设权限，访客可用本站账号登录（每人自己的数据、调用自己的 AI，见下）。侧栏「Clawpages」（`/u/<用户名>/clawpages`，所有账号）按更新时间列出本账号的全部 clawpage（有没有数据都在同一列表、都叫 clawpage，有数据的封面上标记录数）与数据。

- **发布**：经成员网关 `/share/<账号>/pages[/<页面名>]`，只认该运行时的分享令牌（宿主 `<数据目录>/share-token`，沙箱内 0600）。
  同名发布整体替换文件、链接不变、**数据保留**；`list` 带每页的表与记录数；`pull <页面名>` 把已发布文件取回工作区接着改
  （目录已有文件时需 `--force`）；`delete` 同时删除该页全部数据。
- **数据**：每个 clawpage 有自己的表（与 clawpage.ai 的数据表同语义，但按页隔离而不是按账号共享），存在宿主
  `<PA_DATA_DIR>/clawpages.sqlite`，访客读写不解析、不唤醒任何账号的运行时或沙箱。表权限 `private`（访客看不到，读作不存在）/
  `read-public`（访客只读）/ `public`（访客读写）；记录操作：整条写、对象深合并、自动键追加、数值原子加、删除、按插入顺序游标分页
  （每页最多 500）、导入导出。限额：单条 64 KB、嵌套 16 层，每表 1 万条，每页 20 张表，每账号 50 MB；匿名访问按客户端地址与页面
  每分钟 60 次写、600 次读（超出 429）。主人写入不存在的表时自动建为 `private`。
- **页面里用**：`aio-share.py sdk <目录>` 把 `clawpage-sdk.js` 复制进页面（发布时自动刷新这份拷贝），`new Clawpage().table(名).list/get/put/patch/post/incr/delete`
  访问 `/u/<用户名>/share/<页面名>/.data/<表>[/<键>[/incr]]`。该路径 CORS 全开（页面来源是不透明的 `null`）、不用 cookie；用 `file://` 预览时 SDK 改用内存。
- **访客登录（SSO）**：页面调 `cp.signIn()` 跳到自己的 `.auth/sign-in?return=<页内路径>`，再被送到主站 `GET /api/clawpage-sso/authorize`。主站已登录且此前允许过这一页时，
  直接 303 回页面地址并在片段里带 `#cpv=<访客令牌>`（片段不发给服务器，只有该页收到；SDK 取走后立即抹掉）；否则进主站的 `/clawpage-sso` 页：未登录先登录，
  再问一次「允许这个页面知道你是谁（邮箱，没有邮箱的老账号给用户名）、以你的身份存数据、用你的 AI」，允许后（`POST /api/clawpage-sso/grant`，要 CSRF）带令牌回页面，
  不允许则回 `#cpv=denied`。`new Clawpage({ signIn: "auto" })` 每次打开页面先静默问一次（`silent=1`，不出界面，没登录或没允许过回 `#cpv=none`），
  允许过的人回来就是登录状态。返回路径只接受页面目录内的相对路径（含查询），其余一律回页面首页。访客令牌（`cpv1.` 开头）用部署密钥单独签名（与主人链接互不通用），
  只对这一页有效、24 小时过期，每次使用都核对授权仍在；页面里 `cp.signOut()`（`DELETE .auth`）撤销授权，此后令牌立即失效、下次登录重新询问。`GET .auth` 返回令牌对应的人。
  授权记录（谁、邮箱、首次与最近使用）存 `clawpages.sqlite` 的 `cp_grants`，撤销后保留身份以便主人分辨数据归属，删页一并删除。主站的 Google 登录完成后回到控制台，需回页面再点一次登录。
- **登录访客的表权限**：`signed-in`（登录访客都能读、能新增，只能改删自己写的，别人的回 403 `NOT_YOURS`）与 `per-user`（每个登录访客只看到、只改自己的记录，
  键按人隔离：同一个 `put("state")` 各是各的，库里存为 `<账号 id>.<键>`）。两者对匿名访客回 401 `SIGN_IN_REQUIRED`；过期或已退出的令牌回 401 `SIGN_IN_EXPIRED`（SDK 随即把 `cp.user` 置空）。
  每条记录记下首次写入它的登录访客（`author` 列）：主人（控制台、CLI、主人链接、协作者）读到 `by: {id, name, email}`，控制台表格多一列「谁写的」；登录访客读到 `mine`。
- **AI 回答**：`cp.ai.ask(input, { prompt, json, effort })` → `POST .ai`，必须登录。用**访客自己账号**的模型回答（成员为分配的模型、推理强度不超过分配值；owner 为其所选模型，
  Claude 模型走 owner 的 Claude 凭据，其余走控制面的 ChatGPT 登录），在宿主侧直接调用（不唤醒任何沙箱），用量记入该访客账号。只有文字进出：没有工具、联网、记忆，
  也碰不到该账号的文件与历史。系统提示 = 平台说明（页面名、主人、无工具、按要求的语言作答；`json: true` 时只回一个 JSON 对象）+ 页面目录里 `prompts/<名>.md`（≤32 KB，随页面发布，访客可见），
  `json: true` 时服务端解析出 `json`（解析不了为 null）。输入为 `input` 文本或 `messages`（≤40 条、共 ≤6 万字，最后一条是用户），`effort` 为 `low`（默认）/`medium`/`high`。
  限额：每人每页每分钟 10 次、每天 300 次（超出 429）；超时 120 秒。错误码：`SIGN_IN_REQUIRED`、`PROMPT_NOT_FOUND`、`RATE_LIMITED`、`AI_BUSY`（账号额度）、`AI_FAILED`、`AI_TIMEOUT`、`AI_UNAVAILABLE`。
- **主人身份**：控制台点「打开」时由 `POST /api/clawpages/<页面名>/open` 生成主人链接：页面地址后附 `#cp=<令牌>`（片段不发给服务器），
  令牌用部署自己的密钥（`<PA_DATA_DIR>/clawpages-key`）签名，只对该账号该页有效、12 小时过期；SDK 取走后立即从地址栏抹掉。持令牌可读写所有表、不受限流，但不能改表权限或删表（页面脚本可能出自协作者之手；这两项只在控制台与沙箱 CLI 做）。
- **执行器**：沙箱 CLI `data tables|create|permission|drop|list|get|put|patch|add|incr|delete|export|import` 以主人身份操作；每次执行提示词附上本账号
  最近活跃的 12 个 clawpages（地址、发布时间与发布者、协作者数、各表权限、记录数与最近改动时间），主会话因此知道已有哪些 clawpage、数据有什么变化，并按 skill 拉取 → 修改 → 同名发布迭代。
- **版本**：`pull`/`publish` 在页面目录里写 `.clawpage.json`（页面名与所持版本 `updatedAt`，0600，点文件不发布）；之后发布带上 `baseUpdatedAt`，
  页面在此之后被别人发布过就回 409（拉取新版、重做改动再发）。主人不带版本发布时，若当前版本是协作者发的也回 409，`publish --force` 才覆盖。
- **历史版本**：每次同名发布（含协作者发布与恢复）都把被替换的那一版整体移到 `<PA_DATA_DIR>/shares/<账号>/.versions/<页面名>/<版本时间>/`（版本时间是那一版的 `updatedAt`，13 位毫秒；含它的 `.meta.json` 与当时的封面，目录 0700），不再删除。
  保留规则：每页最近 5 个旧版本，整个账号的历史合计不超过 200 MB（超出时在全账号范围内从最早被替换的删起，所以久未改动的页面刚被一次坏发布替换掉的那一版也会留下；元数据读不出的版本直接删，元数据里的版本时间不是 13 位毫秒数的页面目录换版时直接删掉、不进历史）；清理失败不影响发布；删除页面时它的历史一并删除，之后同名再发布从空历史开始。
  恢复入口：控制台 Clawpage 详情里的「历史版本」（默认收起，展开时才读取；列出每版的时间、发布者或「恢复自」、文件数与大小，恢复要点两次），以及沙箱 `aio-share.py versions <页面名>` / `restore <页面名> <版本时间>`。
  恢复的效果：链接不变，只恢复页面文件（和那一版的封面，没有封面就不带封面），**数据表不动**；恢复前的当前版本照常进入历史，所以恢复本身也能撤销，被恢复的那一版也仍留在历史里。
  恢复出的新版本记 `restoredFrom`（来源版本时间）、`updatedBy` 为空，执行提示词里该页会注明 restored from；文件时间按新版本设（至少比上一版晚一秒），访客经 ETag/Last-Modified 立刻拿到恢复的版本，经过 CDN 也一样。
  拿着恢复前版本的协作者，或从旧目录发布的主人（`restore` 不改本地 `.clawpage.json`）再发布会收到 409，需先 `pull <页面名> --force`；只有 `publish --force` 能覆盖恢复。
  只有主人能看和恢复历史：协作接口 `.api` 不提供历史（`.api/versions` 回 404）。接口：控制台 `GET /api/clawpages/<页面名>/versions`、`POST /api/clawpages/<页面名>/versions/<版本时间>/restore`（要会话与 CSRF，只作用于本账号）；
  沙箱经成员网关 `GET /share/<账号>/pages/<页面名>/versions`、`POST …/versions/<版本时间>/restore`（只认分享令牌）。版本时间只接受 13 位数字，否则回 404 `VERSION_NOT_FOUND`。历史目录以点开头，公开路径（`/u/<用户名>/share/.versions/...`、`/u/<用户名>/share/<页面名>/.versions/...`）与页面列表都碰不到它。
- **协作者（别人的 Agent 一起改）**：主人在 Clawpage 详情的「让别人的 Agent 一起改」或沙箱 `invite <页面> --label <名称>` 生成邀请：一个协作者令牌
  （`cpc_…`，库里只存 SHA-256、只在邀请里出现一次、不过期，`collaborators` 列出最近使用时间，`revoke`/控制台随时移除；每页最多 20 个，删页一并删除）
  和协作接口 `https://<工作区域名>/u/<用户名>/share/<页面名>/.api`。邀请文本交给对方贴进任何能发 HTTP 请求的 Agent：
  `GET .api` 返回页面事实、`guide` 与 `prompt`（英文的完整操作说明，含页面的 `AGENTS.md`），`GET .api/prompt` 只给说明文字，`GET .api/files` 取文件与版本，
  `POST .api {files, baseUpdatedAt, title?}` 发布新版本（**必须**基于当前版本，否则 409），`POST .api/cover` 存封面，`.api/data/...` 读写数据（含 private 表、可建表、导入导出）。
  协作者不能删页、删表或改表权限（403），令牌只对这一页有效，接口不开 CORS、无令牌或令牌错一律 401。另一个一站沙箱里用
  `aio-share.py --api <接口> --token <令牌> info|pull`，拉到 `share/remote/<主人>/<页面名>/`，该目录记住接口与令牌，之后直接 `publish <目录>` 发回原页、
  `--remote <目录> data ...` 操作数据，并照常渲染封面。页面元数据记录 `updatedBy`（协作者名称），控制台显示「由 X 更新」。
- **页面指南**：页面目录顶层的 `AGENTS.md` 随页面发布与拉取，写给接手的 Agent（用途、文件结构、各表用途与记录形状），访客路径上一律 404（不分大小写），协作接口的说明里会附上它。
- **封面**：`publish` 发布后，沙箱用 `aio-render` 的无头 Chromium 打开线上页面（访客视角、数据已加载），截 480×640（2 倍密度）的 JPEG，
  经 `/share/<账号>/pages/<页面名>/cover` 存为页面目录下的 `.cover`（只认 JPEG/PNG/WebP 文件头，≤1.5 MB；公开路径不提供隐藏文件）。
  渲染失败不影响发布（输出 `coverError`），`aio-share.py cover <页面名>|--missing` 可重渲；同名重发布保留旧封面直到新封面写入；
  沙箱每次播种后在沙箱里脱离执行一次 `cover --missing`（同一时间只跑一个，日志在 `/tmp/aio-share-cover.log`），
  复用同一个无头浏览器依次为没有封面的页面补上；每页最多等 20 秒加载、8 秒字体与图片，整页超过 60 秒即放弃并换新浏览器；
  封面超过 1.4 MB 时依次降低 JPEG 质量（78→62→48→36）重截。请求体超限时服务端读完再回 413，不中途断开。控制台经 `GET /api/clawpages/<页面名>/cover[?v=<版本>]`
  读取（只给本账号，带版本时长期缓存）：Clawpages 列表与详情用它做封面（没有时用标题首字），主会话里指向本账号 clawpage 的卡片也显示它（左侧竖条缩略图，卡片保持紧凑）。
- **发布检查**：与封面渲染是同一次页面加载（匿名访客视角），渲染器在加载期间收集 Runtime、Log、Network 事件（只留错误与请求相关的几类，缓冲最多 1000 条；每页先切到空白页、读完上一页残留的事件再清空，上一页的定时器和请求不会算到下一页），
  `publish`、`cover <页面名>`、`cover --missing` 的每页结果附 `check`：`errors`（脚本异常与 `console.error`，附位置）、`failedRequests`（状态码 ≥400 或加载失败的请求；
  本页数据接口 `.data`/`.ai`/`.auth` 失败时读取其 JSON 错误响应附上错误码，如 `TABLE_NOT_FOUND`、`PERMISSION_DENIED`）、`blank`（首屏无文字，也无图片/画布/表单控件/iframe 等元素；纯 CSS 方块算空白）、`ok`。
  `TABLE_NOT_FOUND` 既可能是没建表，也可能是表为 private（访客看不到）：skill 要求先用 `data tables` 区分，后者改页面只在 `cp.owner` 时读该表，绝不为通过检查放宽 private 表的权限。
  匿名访客的预期结果（`SIGN_IN_REQUIRED`、`RECORD_NOT_FOUND`）单独列在 `expected`，不算问题；被取消或中止的加载与 favicon 不报。
  上限：每类 10 条（超出时给 `omitted` 总数），每条文字 200 字；最多读取 5 个本页数据接口的错误响应体，每个不超过 4 KB、最多等 3 秒，整页仍受 60 秒闹钟约束。
  本页文件按相对路径报告，第三方地址（含主站）只报主机名，不带路径和查询参数。CDN 给每个页面加的东西（Cloudflare 的 `/cdn-cgi/` 统计信标与预取规则、`static.cloudflareinsights.com`）在页面的不透明来源下必然跨域失败，不算页面的问题，一律不报。页面产生的错误文本视为不可信，截断后只出现在 CLI 输出里给执行器看，
  不上传、不进控制台，服务端不存储（沙箱启动时后台补封面的 `cover --missing` 把输出写到沙箱内 `/tmp/aio-share-cover.log`，其中也有检查结果）；执行器按 skill 修好后重发布（只改数据时用 `cover <页面名>` 复查），检查有问题时不得对用户说页面可用。
  只检查匿名访客视角（不含主人链接与登录访客）；`--no-cover` 时不渲染也就没有检查，渲染超时或浏览器崩溃时只有 `coverError`。
- **控制台**：`GET /api/clawpages` 列表；`/api/clawpages/<页面名>/tables/<表>` 浏览记录（`PATCH` 改权限、`DELETE` 删表）、`/export` 导出 JSON、
  `/records/<键>` 删除单条；`DELETE /api/clawpages/<页面名>` 删除页面和数据。均只作用于本账号。
- **存储与隔离**：快照存在宿主 `<PA_DATA_DIR>/shares/<账号>/<页面名>/`，访问时只读快照，不触碰沙箱。每页最多 200 个文件、20 MB，每账号 100 页；
  路径拒绝 `..`、隐藏文件、反斜杠与控制字符。页面位于工作区来源，响应带 `Content-Security-Policy: sandbox allow-scripts …`（无 `allow-same-origin`），
  读不到工作区会话、cookie 或 localStorage；另带 `nosniff`、`no-referrer`、`noindex`，不设置 cookie。页面文件一律 `Cache-Control: private, no-cache`（只写 `no-cache` 时 Cloudflare 的 Browser Cache TTL 会把 js/css 等改成 `max-age=14400`，重发布后访客最多 4 小时还在跑旧脚本；`private` 它不改写）并带弱 ETag 与 Last-Modified（经 Cloudflare 时 ETag 会被去掉，靠 Last-Modified；每次发布的文件时间至少比上一版晚一秒）：
  每次打开都向服务器确认，未变的文件回 304、不重传，同名重发布后访客立刻看到新版本，不会被浏览器或 CDN 缓存挡住。页面、其 `.data`、`.auth`、`.ai`（后两者凭访客令牌）与凭协作者令牌访问的 `.api` 是全站仅有的不需要登录的路径。

## 15. Claude Code 执行器

默认只有 Codex 执行器。配置 Claude Code 凭据后，配置页出现「执行器」选项，模型列表按执行器过滤（`claude-opus-5-5`、`claude-sonnet-5-5`、
`claude-fable-5-1`，思考强度 low～max，留空按 CLI 默认）。

- **整体切换**：选中后派单与执行都由 Claude Code 完成。派单使用无工具、不落盘的一次性运行（`--tools ""`，模型 `PA_CLAUDE_CODE_AUX_MODEL`）。
  成员账号默认不提供；被分配 `claude-sonnet-5-5` 的成员经成员网关使用。
- **执行方式**：每个轮次在沙箱内启动 `claude -p`（stream-json 双向流），以 `bypassPermissions` 执行；MCP 只挂沙箱内服务（`--strict-mcp-config`）；
  SOUL.md 经 `--append-system-prompt` 注入，工作区 `AGENTS.md` 经配置目录的 `CLAUDE.md` 导入。事件翻译为与 Codex 相同的时间线条目，
  结果、停止与重连沿用同一套机制。
- **会话连续**：控制面预先指定会话 UUID，首轮 `--session-id`、之后 `--resume`。运行中补充写入同一进程，收到回显才算送达；停止通过控制通道
  `interrupt`，15 秒未停再结束进程；无结果退出的轮次标记 `unknown`。
- **切换执行器**：Codex 线程与 Claude Code 会话不能互相派生。已有任务在另一执行器上续接时新开会话，并带入此前的提问与最终回复（约 24k 字符）。
- **固定版本**：CLI 版本为 `PA_CLAUDE_CODE_VERSION`，首次使用时安装到持久卷并关闭自动升级；版本不符时重装并校验。
- **凭据**：`CLAUDE_CODE_OAUTH_TOKEN`（`claude setup-token` 生成）或 `ANTHROPIC_API_KEY`，先读环境变量，再读 `PA_CLAUDE_CODE_SECRETS_FILE`
  （权限宽于 600 / 400 拒绝）。只经 `docker exec -e <变量名>` 传入，argv 中只有变量名；凭据在沙箱进程内可见（CLI 需要读取）。
- **已知边界**：Claude Code 的子代理只以一条工具调用出现在时间线；CLI 的审批与交互式提问不接入。

## 16. 运营看板

owner 侧栏「运营看板」（`/u/<用户名>/analytics`，旧地址 `/usage` 也打开这里）一页合并运营统计与 token 用量，共用一个时间范围（最近 7 / 30 / 90 天），
每分钟并行读取 `GET /api/analytics/report` 与 `GET /api/usage`（都仅 owner）；一边读取失败时另一边照常显示，并提示哪部分可能过期。

- **指标卡**：账号总数、今日活跃、本期任务（完成率）、注册转化、本期 token（输入 / 输出）。点「今日活跃账号」弹出当天活跃账号名单（报表字段 `activeTodayAccounts`）：
  按最近活跃时间倒序，每人显示角色、最近活跃时刻（统计时区）、当天事件数、手动任务数与用过的平台；已删除的账号单独标出。只列账号名，不含邮箱或内容。
- **每日趋势**：活跃账号、任务（完成 / 失败 / 进行中及其他叠加）、新注册各一张柱状图，各自刻度，标题旁给日均或合计，悬停看当天数字。
- **token 用量**：可按用户筛选；按账号叠加的每日柱状图、按用量从高到低排序的用户表（占比、输入、其中缓存、输出；手机隐藏缓存列）与可展开的每日明细。
  token 数用紧凑单位显示（如 6000.4万 / 60M），悬停显示精确值。
- **功能使用与平台分布**：按次数 / 账号数从高到低，数值附比例条；运营每日明细与「统计口径」（任务来源、活跃定义、token 计数范围、各账号采集起点）默认折叠。

token 统计时区取 `PA_BROWSER_TIMEZONE`。计数持久保存在各账号控制数据库，覆盖 Codex / Claude 执行、派单与标题调用。缓存读写计入输入，总 token = 输入 + 输出。
历史只回填已保存的 Codex 用量事件；旧 Claude、旧派单、外部客户端、图片生成与 Jev 不计入，不推算账单或订阅额度。

## 16a. 使用统计（埋点）

自建、不接第三方统计。事件写入控制面中央数据库的 `analytics_events`（时间、事件名、账号 ID、平台、最多 8 个短标量属性），
不记录消息内容、邮箱、IP 或设备标识，启动时删除 400 天前的事件。成员运行时与 owner 共用这张表，上报不会唤醒成员沙箱。

- **平台**：界面每个 API 请求带 `x-client-platform`（`web` / `pwa` / `ios` / `android` / `mac`，由 Mac App 的设备桥、手机 App 的浏览器桥和
  主屏显示模式判断，`src/ui/src/analytics.ts`），服务端只接受这五个值。
- **界面上报**（`POST /api/analytics`，`src/common/analytics.ts` 列出）：`app_open`（加载及离开 30 分钟后回到前台）、`page_view`（切换页面）、
  `auth_view`（登录/注册页曝光，唯一允许未登录上报的事件，需同源 Origin，每 IP 每小时 30 次）。已登录每账号每小时 300 次。
- **服务端记录**：`signup`、`login`（方式、用邮箱还是用户名）、`login_failed`、`logout`、`task_submit`（附件数、是否引用任务）、`task_stop`、
  `task_archive`、`task_retry`、`schedule_edit`、`schedule_action`、`push_subscribe`/`push_unsubscribe`、`locale_change`、`vault_save`、
  `support_request`、`voice_input`（是否成功、时长）、`browser_takeover`/`browser_handback`、`user_browser_takeover`/`user_browser_handback`（本机 Chrome）。新增埋点在 `src/control/http/api.ts` 调 `track()`。
- **统计页**：显示在「运营看板」（见第 16 节；`GET /api/analytics/report?days=7|30|90`，仅 owner）：账号总数与新注册、
  今日 / 7 天 / 30 天活跃账号、任务数与完成率、注册转化（同期注册页浏览与经注册页完成的邮箱注册事件，不含 Google 注册与历史账号）、每日趋势与明细、各事件次数与账号数、平台分布、任务来源。
  活跃 = 当天有事件或手动提交任务的账号（定时任务自动执行不算）。任务数字在读报表时从各账号自己的任务表统计（只读打开，含历史，
  合并进其他任务的补充不单独计）；注册数来自账号创建时间；其余数字从事件开始记录（`meta.analytics_started`）之后才有。

## 17. 界面与交互

- **配置页**：模型与思考强度在统一「配置」页（不在输入区），保存于 owner `meta`（`owner.agent_settings`），跨设备一致，每个轮次提交时冻结。
  输入区只保留附件、语音（配置了 `PA_ASR_URL` 时）、发送与停止。
- **界面语言**：支持简体中文、English、Español 和繁體中文。没在配置页选过时跟随浏览器/手机系统的首选语言（`navigator.languages` 依次匹配，`zh-TW`/`zh-HK`/`zh-MO`/`zh-Hant` 归繁体，其余 `zh` 归简体），都不在这四种内时用英文；配置页的选择优先。语言选择只在配置页提供；普通成员的配置页仅含界面语言及账户与隐私，owner 的配置页保留原有管理项。登录页和侧栏不单独放置语言控件。选择保存在本浏览器/WebView 的 `localStorage`（`aio.locale`），切换后页面重新加载；同时经 `PUT /api/account/locale` 记为账号语言，存在该账号运行库的 `meta`（`account.locale`），从未上报过时默认英文（2026-10-18 起；此前默认简体中文，升级时已有任务、又没记过语言的账号一次性记为简体中文，记 `account.locale.legacy_checked`）。配置页的选择总是生效，并记下「已手动选择」（`account.locale.manual`），此后自动来源不再覆盖它；自动来源有两个：每条消息随 `POST /api/tasks` 带上的 `locale`，以及没选过语言的控制台登录后上报一次的系统语言（`sync: true`，每个账号只采纳第一次，记 `account.locale.synced`；本机也记 `aio.locale.synced` 不再重发，且不计入 `locale_change` 埋点）。用户消息保持原文。服务器写给人看的文字（错误信息、任务与浏览器状态说明、定时规则描述与回复、通知、工作区的提示页等）同样四种语言，词典在 `src/control/i18n/locales/<语言>/<区域>.ts`（中文为基准形状，其他语言同形）：请求按控制台随每个 API 请求带上的 `x-aio-locale` 回答，没有时按浏览器的 `Accept-Language`，都不在四种内时用英文；运行时自己发起的工作（任务执行、定时器、推送）按该账号语言。只给模型或日志看的文字用英文写在代码里；沙箱内脚本与沙箱节点只写英文和错误代码，由控制面按代码换成对应语言。写进数据库的说明按写入时的语言保存，旧记录不改写。日期与数字按控制台语言格式化。公开页同样四种语言（`/about.html`、`/privacy.html`、`/terms.html`、`/account-deletion.html`）不走界面词典：每页按语言各写一份完整正文，由 `src/ui/public/policy-lang.js` 依次按 `?lang=`、`aio.locale`、浏览器首选语言选定（规则同上），未启用 JavaScript 时显示英文；页内语言切换链接带 `?lang=`，见 `docs/play-console.md`；Mac App 的名称与麦克风授权说明按系统语言（英文为基础）。
- **提示词与回答语言**：派单器、执行者、Jev、语音配件、每日推送与定时运行的提示词，以及工具和技能说明，全部用英文书写（`src/control/locale.ts`）；输出给人看的提示词（执行轮次、追加补充、语音配件、派单器——其 `title` 会显示）最后一行注入语言要求：用户可见内容（任务标题、回答、卡片和交付文件）用用户这条消息本身的语言书写，消息看不出语言（只有链接、数字、名字或表情）时才用账号语言；定时运行（含每日推送，指令可能是系统写的）直接用账号语言。语音输入润色不注入，保持用户所说的语言。控制台从执行提示词里取出用户原话时（`src/ui/src/dispatchText.ts`）同时识别英文与旧的中文提示词，并去掉末尾的语言行。繁体版使用独立静态词典，没有运行时转字依赖。
- **移动端导航**：左上角按钮打开侧栏；主会话、工作区、配置、主题与退出入口都在侧栏。弹窗、预览、地图选择与操作面板从底部滑入，
  导航侧栏从左侧滑入；开启「减少动态效果」时直接开关。
- **输入区**：移动端为悬浮卡片，空白未聚焦时收成单行，聚焦或有草稿、附件、引用时展开，高度不超过可用屏幕。触屏设备上输入框与下拉框统一 16px
  （iPhone Safari 会放大字号更小的输入框且不缩回）。按钮使用图标与无障碍标签。
- **加载动画**：全站所有加载（启动页、登录恢复、页面与面板里的「正在读取…」、打开链接、上传与发送中）用同一个动画：单线条简笔勾出一站标志的轮廓（先描圆角外框，再画进站线段、绕站点画圆、出站线段，最后点上站心），停顿后淡出循环；单色线条，按钮里随按钮文字颜色，图片上为白色。页面上所有加载动画按同一时钟同步；开启「减少动态效果」时只显示画好的轮廓。
- **长消息**：用户消息与任务回复最多显示一屏可用高度，超出时点击打开约九分屏的底部阅读面板，返回后保留位置与草稿。
- **图片预览**：竖图按高度、横图按宽度完整显示，高度用 `100dvh`（iPhone Safari 的 `100vh` 大于可见区域）。
- **内网链接与操作面板**：智能体操作浏览器不会自动展开工作区。内网 IP 链接在沙箱浏览器中新开一个仅属于你的标签页（独立窗口），并弹出操作面板：
  - 手机（视口 ≤ 720px）上由控制台的手势层操作（与「Mac 上的浏览器」相同）：点按点击、单指拖动先平移放大的画面再滚动页面、双指捏合缩放并平移（1～5 倍）、
    双击放大或还原、长按后拖动为按住左键、双指轻点为右键；默认按 1.3 倍屏宽居中显示；电脑上由 noVNC 自己整屏适配；
  - 画面下方是桌面工具栏（键盘、粘贴、回车、Tab、Esc），不再靠它左右平移；键盘弹出时画面大小不变、操作栏留在键盘上方；
  - 这类标签页智能体不可见也不可操作，最多保留最近 3 个，关闭面板即关闭；标签页服务不可用时退回为打开工作区浏览器；
  - 打开过程显示加载卡片（可取消，超过 8 秒提示浏览器可能在唤醒，60 秒无结果自动放弃并说明原因）。
- **noVNC 补丁**：镜像自带的 noVNC 1.4.0 在手机上一次点按发两个键、长按会按住右键（导致「按住确认你是真人」无法通过）、捏合发送 Ctrl+滚轮
  （Chrome 会按站点记住缩放）。控制面在沙箱启动时打补丁（`src/control/sandbox/novncPatch.ts`）：一次点按一个键，长按 1 秒按住左键，双指点按为右键，
  捏合不再缩放远端页面；手机上控制台的手势层盖在 noVNC 上，经 postMessage 发来点击、按住拖动与滚轮（滚轮按 50 像素一格换成 VNC 的滚轮键），补丁按帧缓冲坐标直接发指针事件。
  补丁改动后要升 `NOVNC_ASSET_VERSION`（与 `DESKTOP_PATH` 的 `aio=` 一致），并且先上线控制面（重启后各沙箱重新打补丁）再上线界面。
- **品牌与配色**：品牌名「一站」，配色语义为靛紫 = AI 在办（品牌主色）、琥珀 = 轮到你（全站唯一醒目色）、松绿 = 办完、朱红 = 出错；
  令牌定义在 `src/ui/src/styles.css` 顶部，新界面只用这些令牌。
  任务卡片以标题为主（正文色、加粗、一行省略），状态是旁边的小字：已完成松绿、执行失败与结果未知朱红、已中断灰、正在回复靛紫；进行中卡片的「在办」等状态字小于标题，只有轮到你的琥珀状态保持醒目。
