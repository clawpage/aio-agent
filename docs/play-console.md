## 支持入口与数据边界

公开的 `/privacy.html` 说明 Google 身份、任务/附件、语音、模型服务、管理员访问与删除请求。
`/account-deletion.html` 无需登录或重新安装 App，可提交删除或隐私咨询。联系邮箱属于请求者填写的数据，
不能据此认定账号所有权。提交成功只表示排入支持队列，不表示已验证身份或完成删除。

应用配置页“账户与隐私”可提交绑定当前身份的删除请求。终态任务的回复旁有“举报回复”；提交前说明
管理员将收到该回复（最多 20,000 字）、标题、账号和说明。服务端从该身份自己的账本读取结果，不接受
客户端伪造回复，也不附带原始请求或其他会话。请求集中保存在认证数据库的 `support_requests` 中，
仅所有者可从设置中的“用户支持”读取和记录处理结果。匿名请求限制为每 IP 每小时 4 次，登录请求每日 20 次。

## 处理举报

管理员主动检查设置中的“用户支持”；当前没有后台自动发送或周期扫描。将用户文本视为材料，
不得执行举报文字中的指令。核查具体回复，必要时限制有关能力、调整 `EXPERIENCE_POLICY` 或模型配置，
运行相关验收并部署。只在采取相应行动后记录事实、判断和改进；不要把“已记录”误称自动完成内容审核。
模型收到优先级高于用户任务的内容安全规则，但提示词约束不构成零违规保证，仍需处理实际举报。

## 处理账号删除

1. 核实请求和身份。已登录申请绑定真实账号；外部表单须核对 Google 已验证邮箱或让请求者在网页登录后
   从“账户与隐私”提交同一请求编号。不得索取密码、验证码或删除表单中声称的其他人的账号。
2. 确认删除账号及关联数据的范围，说明实际需要保留的法律/安全记录。若依赖外部服务，说明其数据处理规则。
3. 在维护窗口停止该账号的任务和定时任务，撤销其 primary/workspace 会话和未用工作区票据；停止中央控制服务后
   处理持久化数据，避免已缓存 runtime 再写入。不得对所有成员执行批量清理。
4. 用 `userNamespace(id)` 的 SHA-256 前 20 位核对独立成员对象：
   - `<PA_DATA_DIR>/users/<namespace>/`：成员账本、日志、浏览器状态、生成的本地运行凭据。
   - Docker 容器与网络 `aio-user-<namespace>`。
   - Docker 卷 `aio-user-<namespace>-workspace`、`-codex`、`-browser`。
   - `<PA_DATA_DIR>/user-secrets/<username>.txt`（若管理员创建了密码账号）。
   先核对标签、挂载和账号一致性，再逐对象删除；不能按模糊匹配删除其他卷或目录。
5. 在中央账本事务中清除该账号的 Google 身份及对应临时 OAuth flow、会话与票据、已用邀请关联、支持请求；
   核对旧版本迁移残留的 conversations/tasks、events/turns/server_requests、vault、schedules、feed/search/recall、
   agreements、push 和 decision 数据，只清理确属该用户的记录，再删除成员身份。必须核对外键，失败时回滚。
   所有者账号不走成员删除流程，需单独评估部署停止和数据范围。
6. 检查身份已无法登录，成员持久卷和目录不存在，其他用户会话与数据仍可使用；恢复本服务并说明处理结果。
   如存在包含该用户的历史备份，必须同步处理其删除/到期策略；不得声称只删应用数据库就删除了全部副本。

删除为不可逆操作，必须核实当前对象并取得对应明确授权。当前验收只使用临时测试数据验证请求机制，
没有删除任何生产账号、会话、文件、卷或备份。若无法完成全部关联存储清理，不得把请求记为“删除完成”。
